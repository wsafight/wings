# ADR-0004：抢占、精确根与 GC

- 日期：2026-11-12
- 状态：已采纳（设计）

## 背景

公平调度需要让纯计算 handler 也能让出，GC 则需要在暂停时找到全部活跃引用。直接从任意机器指令切走，或猜测原生栈中的指针，都不足以支持精确恢复。

## 决定

- 计时线程通过原子标志请求抢占，编译器在受控 safepoint 轮询，优化后检查覆盖。runtime 长操作分块让出或限制输入规模。
- 初版使用显式 shadow stack 枚举精确根，切换只发生在满足受管 ABI 的位置，恢复包括全部活跃值和正确的 worker 绑定。
- 初版为进程内、非移动的精确 mark-sweep GC，小堆完整回收起步；增量方案由停顿数据决定。
- 栈池有容量上限与 guard page，分配栈空间前检查显式限额。不允许 Rust panic/unwind 跨越受管边界。
- 首版不依赖信号抢占、不透明增长原生栈，也不在未知 `SIGSEGV` 后继续执行。

## 替代方案

- 信号异步抢占：线程定向、信号栈和 live value 恢复更复杂，先不采用。
- stack map：可以减少根发布成本，但后端元数据与双平台恢复需要单独验证。
- 移动或分代 GC、显式续体：列入优化候选，改变默认模型前另作决定。

## 影响

原子轮询、根维护、栈池和 GC 都增加成本，必须完整计入 BEAM 对照。普通 macOS/Linux 下的延迟目标有负载与机器条件，不承诺硬实时。

## 重审条件

根维护、保留执行栈或 GC 停顿成为主要瓶颈时，可以提出替代设计，但必须保留正确性基线，并重新验收 ABI、根完整性与取消响应。
