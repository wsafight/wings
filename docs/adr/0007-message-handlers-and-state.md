# ADR-0007：统一消息入口与具名状态

- 日期：2026-11-12
- 状态：已采纳；前端子集已实现，执行语义待实现
- 替代范围：[ADR-0002](0002-language-and-aot.md) 中借鉴 Elixir 消息写法的选择；单前端与 AOT 决定不变

## 背景

旧原型沿用 GenServer 式入口与返回 tuple。业务代码需要记住不同入口、状态绑定和返回位置，参数却没有明确类型。这些写法主要服务于库的回调协议，Wings 既然内建进程，就不必要求用户重复描述分派和状态返回。

参考 Gleam 的类型与表达式、Pony 的消息入口、Rust 的显式签名，并保留 Erlang 的进程隔离和监督方向。只改变表面语法，不借此引入阻塞等待、共享可变值或事务承诺。

## 决定

- 使用 `process`、具名 `state` 和统一的 `on`，块使用 `{}`；不保留旧语法兼容分支。
- 状态、消息字段与回复类型显式标注，局部 `let` 可以推导类型。类型与消息名使用大写开头的名称，不用 atom 表示类型。
- `on` 声明定义消息字段和可选回复类型，不另写重复的消息枚举。同一进程内消息名唯一，不按签名重载。
- 有 `-> T` 的入口处理请求，尾表达式作为自动回复；没有 `->` 的入口处理单向消息且块结果须为 `Unit`。`-> Unit` 仍需回复，与单向消息不同。
- 只允许替换状态绑定；业务值、参数与 `let` 保持不可变。候选状态只在正常结束时提交，提交后才尝试自动回复。失败不保证进程继续运行。
- `send`、`request`、`spawn` 的副作用时机维持原决定：调用点生效，后续失败不撤回。`request` 不同步等待业务结果。
- 语句用换行或 `;` 分隔；未被 `;` 终止的尾表达式是块结果。类型检查拒绝赋值给参数和局部绑定，也拒绝把非 `Unit` 尾值当作单向消息结果。

## 替代方案

- 继续缩短旧关键字：没有消除回调返回协议和重复状态绑定，不采用。
- 把进程写成普通对象方法：容易把请求误读成同步调用，也隐藏消息与本地函数的区别，不采用。
- 完全纯函数式地返回新状态和回复：提交边界清楚，但每个入口都需要包装结果。内部表示可以保留，业务语法不暴露。
- 引入 `async`/`await`：会改变活跃执行帧、续体和冬眠约束，本决定不涉及。

## 影响

前端、检查器、LSP 与示例一并迁移。消息字段名和回复类型必须进入语义模型，不能只保留参数变量名；LSP 复用这些信息显示类型。编译后端需要把状态替换降为候选值与提交操作，并在分配、GC 和 safepoint 处维护根。

消息构造、系统事件、跨模块协议、发送错误类型及执行后端尚未实现。当前检查通过只说明已支持子集的静态规则成立，不代表状态提交或消息投递已经运行验证。语法本身不保证性能或内存优于 BEAM。

## 重审条件

真实业务需要延迟回复、跨模块协议复用、复杂状态记录或等待语法，且当前模型无法清楚表达时，另提决策；不通过隐式重载改变请求、单向消息或提交语义。
