# ADR-0009：标量 AOT 执行原型

- 日期：2026-11-12
- 状态：已采纳（M0 原型）；完整受管执行模型仍待验证
- 发布更新：原型完成双平台 CI 后，维护者同意将十个已有实现的包按 `0.0.2` 发布；原先不可发布的准备状态结束，范围与流程见[包发布](../publishing.md)。执行模型和可信边界不变。
- 相关决定：[单前端与 AOT](0002-language-and-aot.md)、[受管根与抢占](0004-safepoints-and-gc.md)、[包边界](0006-workspace-and-lsp.md)

## 背景

现有前端只能检查程序。先用不分配业务堆、无循环和递归的直线 handler 验证真实对象生成、系统链接、装载、状态提交与错误返回，不能将这个原型当作完整微进程 VM。

## 决定

- 使用 Cranelift 0.118 的本机 AOT 对象后端，通过系统 `cc` 链接共享库；目标限定 macOS AArch64 与 Linux x86-64，不提供 JIT 或解释执行替代路径。
- 建立实际被调用的 `wings-abi`、`wings-ir`、`wings-artifact`、`wings-codegen` 与 `wings-vm`；新包先保持 `publish = false`。不建立 `wings` 聚合包。
- 编译器从通过语义检查的单个 process 降到有界、类型化的直线寄存器 IR；代码生成不依赖语法或语义库，VM 不依赖编译器。
- 原型支持 `Int`（有符号 64 位）、`Bool`、`Unit`。整数运算检查溢出；除法向零截断，除零及最小整数除以 `-1` 返回错误，不触发硬件 trap。取负溢出也失败。
- 标量 ABI v1 使用 C 调用约定：`(state: i64, args: *const i64, output: *mut ScalarOutput) -> u32`。输出是两个连续的 `i64`（候选状态、回复）；Bool 编码为 0/1，Unit 为 0。参数由宿主按清单校验并提供，无 Rust 容器或 unwind 跨边界。这个原型 ABI 不替代后续包含 context、根链与抢占的受管 ABI。
- 产物是新建目录，包含有界 JSON 清单和固定名称的共享库；校验格式版本、标量 ABI、目标、字段、入口数量与参数类型。来源与代码安全不能由 JSON 校验保证，VM 只在显式 `--trusted` 后装载本机可信编译产物，不承诺运行不可信输入。
- 初始化与每次 handler 调用只在成功后提交状态及回复；失败终止该原型实例，不继续分派后续输入。单向入口与 `-> Unit` 保持区别。
- VM 启动时装载一次，共享库保留到 OS 进程结束，不提供热卸载。stdin 的逐行 JSON 只是原型驱动协议，不是语言内阻塞 receive，也不是 mailbox 或网络 API。

## 替代方案

- 先实现解释器：不能降低 AOT、平台 ABI 和装载风险，不采用。
- 一次实现调度、GC 和完整资源账本：会推迟最小后端反馈，先完成独立标量切片，但不降低 M0/M1 的验收要求。

## 影响与验证

编译器新增 `build`，原有 `check` 与 LSP 不执行程序。主机需要 C 链接工具链，前端仍保持 Rust 1.85 基线。验证 Counter 的连续状态、Bool/Unit、参数错误、算术失败、失败后无成功回复及错误产物拒绝。两个平台均需实际执行；只有本机通过时，另一平台明确标记待验证。

本原型尚无 safepoint、活栈切换、shadow stack、GC、mailbox、三级资源账户、监督或 BEAM 对照，不用于不可信业务和生产部署，也不据此宣布 M0 完成。

## 重审条件

接入循环、函数、业务堆引用或 runtime 调用前，先补齐 context、强制 safepoint、精确根、栈限额与让出恢复契约；不能把这个 ABI 直接扩展成未经验证的完整受管 ABI。
