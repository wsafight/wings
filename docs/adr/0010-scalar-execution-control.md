# ADR-0010：标量执行预算与受管取消

- 日期：2026-11-12
- 状态：已采纳（M0 原型设计）
- 后续：[ADR-0011](0011-scalar-stackful-resume.md) 扩展未发布源码为 ABI v3，增加原栈让出恢复，保留总预算和失败提交语义。
- 替代：[ADR-0009](0009-scalar-aot-prototype.md) 的标量 ABI v1；可信装载与标量范围不变
- 相关决定：[抢占与精确根](0004-safepoints-and-gc.md)

## 背景

`0.0.2` 的标量原型只能运行至返回，尚无执行控制。先在仍无循环、递归和业务堆的代码中验证编译器强制检查、预算失败与取消的提交边界，再接入活栈切换。取消不是暂停后重放 handler，也不能用 Rust unwind 跨越生成代码。

## 决定

- 未发布源码使用标量 ABI v2，在原签名末尾增加 `*mut ScalarContext`；清单 ABI 不匹配就拒绝装载，不猜测旧签名。已发布 `0.0.2` 仍为 v1，不覆盖或追加发版。
- context 使用 C 布局，包含指向稳定 `AtomicU32` 的只读指针和剩余 `u64` 步数。宿主确保指针有效、对齐且在整个调用期间存活。context 仅供唯一执行线程访问；取消标志可跨线程原子写入。
- 每条标量 IR 指令之前和正常输出提交之前检查一次：先以顺序一致原子读取取消标志；非零则返回取消状态；否则预算为零则返回耗尽状态，再扣除一步。由后端固定插入，不由业务代码选择，编译优化不能删除或合并检查。直线函数包含 N 条 IR 指令时，成功需要 N+1 步。
- 默认初始化与每次 handler 分别获得 1,000,000 步。库调用可指定 handler 预算和共享取消令牌，命令行可指定每次 handler 的 `--max-steps`；这不是 CPU 时间、租户计费或完整抢占预算。
- 取消令牌一旦取消就不重置，避免迟到请求污染下一次调用。库调用者决定令牌是否跨调用共享。检测取消或预算耗尽时不写候选状态与回复，实例按受管失败终止；在最后一次检查之后到达的取消不能撤回已成功完成的调用。
- 不引入慢路径回调、协程或额外栈，不提供暂停、恢复、GC 根或调度器。不声称解决完整 M0；后续恢复必须保留原活栈，不能重放副作用。

## 替代方案

- 只在宿主调用前检查：无法验证生成代码的受管检查，也不能支持后续长 handler 的响应边界。
- 同时实现协程与调度：错误与资源边界过多，先验证无 unwind 的终止路径，再单独验证原栈恢复。
- 按机器指令或耗时计步：受后端和平台影响，不适合作为此切片的确定性正确性基线。

## 验证与影响

两个首要平台均需验证默认行为不变、零预算、逐个检查点耗尽、提交前耗尽、预先取消、取消优先级和错误后不再处理后续消息；直接 ABI 调用以哨兵值确认失败未写输出。旧 ABI 必须拒绝装载。测试在限 CPU、禁 core dump 的隔离 OS 子进程内执行；此阶段不声称已验证并发取消延迟、活栈或精确根。

增加原子轮询与计步成本，不作为性能优化成果。仍需后续双平台 BEAM 对照。新源码没有新 crate 版本；安装说明继续明确区分已发布 v1 与未发布源码 v2。

## 重审条件

接入循环、函数、业务堆、分块内建或活栈恢复前，更新检查覆盖与根发布契约。调整计步粒度、取消优先级或恢复模型时重新验证所有失败提交边界。
