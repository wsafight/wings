# ADR-0011：标量 handler 的同线程活栈恢复

- 日期：2026-11-12
- 状态：已采纳（M0 原型设计，实施前记录）
- 替代：[ADR-0010](0010-scalar-execution-control.md) 的标量 ABI v2 及“不提供让出恢复”的阶段限制；总执行预算和失败提交语义保留
- 相关决定：[受管根与抢占](0004-safepoints-and-gc.md)、[标量可信边界](0009-scalar-aot-prototype.md)

## 背景

原子取消能终止 handler，却不能让其他微进程获得运行机会。下一步先在仍无循环、递归和业务堆的原型中验证原栈恢复，避免把重放 handler 当成恢复。这里没有受管堆引用，不能据此声称验证了 shadow stack 或 GC。

## 决定

- 未发布源码改为标量 ABI v3，入口签名保持四个参数，扩展 C 布局 context：取消指针、总剩余步数、原子让出请求指针、当前时间片剩余步数、可空慢路径函数指针和 opaque 数据指针。v1/v2 清单在装载库前拒绝，已发布 `0.0.2` 不变。
- 每个强制检查点按顺序处理取消、总预算耗尽、让出请求/时间片耗尽，最后同时扣减总预算与时间片。取消和总预算耗尽是终止，时间片耗尽是暂停。慢路径正常返回后重新检查取消与总预算；同一条 IR 不重复执行，也不重复扣费。
- 慢路径遵守 `unsafe extern "C" fn(*mut ScalarContext) -> u32`。非零状态立即返回且不提交输出；无回调却要求让出返回明确控制错误，不调用空指针。回调不能 unwind、递归进入同一实例、保留 context 或跨线程恢复。
- 使用 `corosensei 0.3.3` 的固定大小 guarded stack，关闭默认 feature，仅启用 `default-stack`，不启用 `unwind`/`asm-unwind`。单次活跃调用分配 256 KiB 可用栈，另有平台页对齐与 guard page 成本；分配失败先返回，不终止未执行的实例。不宣称已有栈池或三级资源账本。
- `ScalarExecution` 在整个调用期间独占借用实例，拥有参数、取消令牌及协程；不能 Send/Sync，只能原线程恢复。每次 `resume` 接受非零时间片，返回挂起或完成。成功完成才提交候选状态与回复；已完成的 handle 再次恢复返回错误，不 panic。
- 共享让出令牌允许其他线程请求让出，但本切片不实现计时线程、worker 或迁移。慢路径在暂停前清除已观察的请求；暂停后的新请求保留到后续检查，允许合并重复请求。迟到取消/让出不撤回已完成调用。
- 丢弃未开始或已挂起调用将实例标记失败。挂起时用内部取消命令恢复一次，慢路径返回取消状态，生成代码沿正常返回路径退出，再释放栈；绝不强制 unwind 或 `force_reset`。可信代码若违反取消返回契约而再次挂起，终止 OS 进程，不尝试继续使用损坏的执行上下文。
- 既有同步 `invoke` 和 CLI 继续直接调用，用无限大的时间片且不安装回调，保留总预算和原子取消检查；不无故为每条同步消息分配协程栈。

## 验证

在限 CPU、禁 core dump 的独立 OS 子进程中验证每一步让出、原栈活跃值、恰好足够的总预算、不重放、挂起时取消、Drop 清理、两实例交错、算术失败、零时间片拒绝、重复恢复错误及旧 ABI 拒绝。debug 和 release 均运行同一行为检查，macOS AArch64 与 Linux x86-64 必须分别通过 CI。浮点/SIMD、GC 根、迁移、guard page 故障注入和并发取消延迟仍是后续验收，不能借用标量结果宣称完成。

## 替代方案与影响

- 重放 handler：会重复外部副作用，违反现有语义，不采用。
- 手写两个平台切换汇编：先使用已有切换库，减少此阶段的 ABI 实现面，但仍必须双平台实际执行。
- 保存 IR 程序计数器并解释续跑：绕过原生活栈恢复风险，不满足本次 AOT 验证目标。

固定栈增加暂挂调用内存；逐 IR 检查不是最终性能粒度。后续必须在三级资源准入与栈池中核算，不能以此作为内存目标已经达成的证据。加入堆引用、控制流、runtime 内建或跨线程迁移前，先补齐根链、栈限额和相应恢复契约。
