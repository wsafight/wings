# ADR-0012：自主管理的有界原生栈池

- 日期：2026-11-12
- 状态：已采纳（M0 原型设计，实施前记录）
- 替代：[ADR-0011](0011-scalar-stackful-resume.md) 的每调用独立 `DefaultStack` 分配策略；ABI v3、原栈恢复和取消语义保留

## 依据与决定

macOS AArch64、16 KiB 页上，512/2048 个栈、三次独立重复显示：浅栈物理增量约 16 KiB/个，256 KiB 可用容量不是 256 KiB RSS。改为 32/64 KiB 主要减少虚拟预留，无法消除页粒度及挂起时的活栈。深栈实测增量随触碰页增长。完整条件与结果见[栈实验记录](../evaluation.md#原生栈分配实验)。没有相同业务负载的 BEAM 对照，不能宣布内存目标达成。

- 自主管理 `StackPool` 的 mmap 预留、guard page、槽位准入、缓存与回收；继续只使用 corosensei 的切换实现，禁止 unwind。更换汇编不会消除保留活栈和物理页的成本，暂不重写。
- 每个池一次预留若干固定大小槽位，每个槽位包含一个低地址 guard page。按平台真实页大小向上对齐；只有借出时才将可用区设为可读写。不可执行，不透明增长，未知越界仍终止 OS 进程。
- 池同时限制槽位数、单栈容量和缓存个数，全部在分配前检查。默认每线程共享池最多 64 个槽位，每个可用容量 256 KiB、最多缓存 2 个已完成栈；其他配置使用显式池。这个上限只是原型的栈池准入，不替代进程/租户/VM 三级账户。
- 缓存只允许用于已经正常返回的栈。取消也必须先沿受管 ABI 正常返回。活跃/挂起栈独占槽位，不能复用、清页或迁移；`resume` 返回完成时立即归还，不等 handle 被丢弃。
- 超出缓存上限的已归还槽位用固定地址匿名 `PROT_NONE` 重映射，丢弃已触碰页，并恢复整个槽位保护；保留池的地址空间，供后续借出。缓存槽位仍占实际内存，计入统计，`trim` 显式回收。重映射失败不伪报已释放，保留安全映射并记录失败，允许缓存暂时超过目标但不超过池总容量。
- 每个池同线程使用、不能 Send/Sync，借出栈持有池的共享所有权。池 handle 被丢弃不能提前 unmap 活栈；最后一个所有者退出才解除整块映射。池耗尽返回错误，不使尚未执行的微进程失败。
- 统计报告保留地址、guard 页、可用容量、活跃/缓存/空闲槽位与重置失败；容量不是 RSS，不用逻辑统计代替 OS 物理测量。guard page 依然可能导致约两个 VM region/活跃槽位，整块预留不保证减少峰值 region。

## 验证与限制

先验证池容量拒绝、复用、完成即归还、挂起/未启动 Drop、独占性、缓存上限、trim 与池先于活栈 Drop。再按相同 AOT 活跃值负载复测峰值和回收后物理占用，以及反复调用的分配开销。所有栈探测使用有 CPU/墙钟限制、禁 core dump 的子进程和有界数量，不做宿主 OOM。双平台分别运行正确性 CI；当前实验驱动只在 macOS 读取物理占用与 VM region，Linux 测量待补。

不直接缩小业务栈作为“优化”：小栈实验通过不证明所有受支持产物可安全运行。接入控制流、递归和内建前仍需编译器栈限额检查。栈池主要解决容量控制、分配复用与空闲回收，不能消除大量同时挂起原生栈的下限。若代表性负载仍不达标，按独立 ADR 评估显式续体，不回放 handler，也不删除安全检查换数据。
