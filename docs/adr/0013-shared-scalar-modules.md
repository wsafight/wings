# ADR-0013：共享标量模块与预解析 handler

- 日期：2026-11-12
- 状态：已采纳（M0 原型）；未发布源码已实现，本机 debug/release 验证通过，双平台 CI 待验收
- 相关决定：[标量 AOT](0009-scalar-aot-prototype.md)、[活栈恢复](0011-scalar-stackful-resume.md)

## 背景与决定

当前每个实例重复读取清单、分配 handler 元数据及符号表。它们不是可变业务状态，应按模块共享；每次消息又按名称查找 handler，不适合作为后续 mailbox 的内部表示。

- `ScalarModule::load_trusted` 校验一次清单并解析原生符号，模块以只读共享所有权持有清单、initializer 和入口数组。`instantiate` 每次执行 initializer 创建独立的标量状态和失败标记，不缓存初始化结果、不共享可变业务状态。
- `ScalarProcess::load_trusted` 保留为便利入口，内部装载模块再实例化。多个实例要共享时显式复用同一个模块，禁止自动按路径缓存而忽略文件变化。
- `HandlerId` 由模块按名称预解析，内部持有模块所有权及入口序号；直接调用前核对模块身份和参数 schema，再用序号索引入口。不接受来自其他模块的 ID，即使清单同名或序号一致；ID 不是可持久化或跨进程协议值。
- 名称查询保留在兼容接口和外部 JSON 适配层；内部重复调用可复用 ID，避免每次重复字符串分派。该切片不是语言级消息 tag、mailbox 或多态特化。
- 共享库继续按现有静态原型契约保留至 OS 进程退出，不新增卸载或热更新。可共享的元数据在最后一个模块/ID/实例释放后销毁；不会因为模块 handle 被释放而使活跃实例失效。

## 验证与边界

验证同模块多实例的状态和失败独立、每次初始化、模块 handle 先释放、错误模块 ID/参数/未知名称拒绝，以及名称调用和 ID 调用结果一致。测每实例布局和相同 AOT Idle/挂起负载的 OS 物理增量，不把固定字段大小当作 RSS。保持 VM 不依赖前端，LSP 不依赖代码生成；ABI v3 与产物格式不变。

这只减少重复元数据及查找，不涉及 record/字符串堆、GC 或完整资源账户。未完成同负载 BEAM 对照前，不宣称性能或内存目标达成。
