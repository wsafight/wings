# ADR-0014：单 worker 三级资源预留账本

- 日期：2026-11-12
- 状态：已采纳（实现契约）
- 相关决定：[微进程与资源模型](0003-process-and-resource-model.md)

## 决定

先实现单线程可验证的 VM → tenant → process 三级账本，为后续有限 mailbox 和调度器提供准入原语，不提前接入堆或语言内建。

- `ResourceAccount` 只能按三级关系创建；根、租户、进程分别配置 bytes、processes、messages、requests 四类上限。子账户通过共享所有权持有父账户，父 handle 释放不破坏未完成预留。账户同线程使用，不承诺 M:N 原子性。
- `reserve` 在修改任何一级前，先逐级检查四项加法溢出和额度。全部成功才一次性增加各级已用值，返回不可克隆的 `Reservation`。额度失败或整数溢出不改变账本，调用者必须在预留后才申请业务资源。
- `Reservation` 的 Drop 逐级归还额度。它必须与真实资源一起存活，不能先释放票据再继续持有资源；账本本身不能强迫第三方代码遵守分配顺序。
- `transfer` 只允许同一 VM 内的账户。共同祖先额度保持不变，先校验目标独有祖先的增量，成功后才转移源独有祖先额度。目标失败不改变原所有权，也不临时双计共同祖先。跨 VM 转移需未来显式协议，当前拒绝。
- 资源数量和字节都用 u64，zero 预留合法且无增量。计费是约定容量，不是 RSS；对象头、对齐、队列容量、临时编码、预留控制记录与池缓存须由后续调用者纳入，不能只计 payload。

## 验证与接入边界

独立受限子进程验证三层分别拒绝、四维额度、溢出、零预留、Drop 回滚、同账户/跨租户/跨 VM 转移、共同祖先已满时仍能净转移，以及账户 handle 提前 Drop。后续调度器必须用此账本控制进程数、mailbox、请求表与活跃栈；目前只是独立原语，不能把单例 CLI 称为已有完整资源隔离。

本切片不修改语言、ABI、GC 或线程模型。扩展为 M:N 前必须先定义跨 worker 准入和所有权转移同步，不能直接给当前内部可变状态添加不受证明的 Send/Sync。
