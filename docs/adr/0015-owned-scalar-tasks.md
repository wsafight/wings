# ADR-0015：可移动的单线程标量执行槽

- 日期：2026-11-12
- 状态：已采纳（M0 实现契约）；双平台结果以本分支 CI 为准
- 补充：[活栈恢复](0011-scalar-stackful-resume.md)、[共享模块](0013-shared-scalar-modules.md)

## 背景与决定

`ScalarExecution<'_>` 独占借用实例，适合宿主直接驱动，但不能与它借用的实例并排放入可移动的进程表槽位。给实例添加稳定裸指针或自引用容器会扩大 unsafe 边界，也没有必要。

- 将参数、令牌、handler 索引和协程收拢为私有 invocation；它不借用实例，只捕获调用开始时的标量状态和入口。返回值仍是候选输出，由实例在成功结束后校验、提交。
- 保留已有借用接口及失败行为。新增 `ScalarTask`，按值拥有实例及至多一个 invocation；不添加进程身份、队列或调度器，不把它称为完整 actor。任务可以在同一线程内移动，不能 Send/Sync。
- `start` 使用模块绑定的 `HandlerId`、显式栈池和控制令牌。忙时拒绝第二次开始；schema 错误或池耗尽不改变实例、不取得执行权。挂起期间外部不能访问可变实例，避免同步调用与未完成调用交错。
- `resume` 只允许非零时间片。挂起保留原栈；成功结束才提交，失败终止实例；完成或失败立即归还栈。取回实例 `into_process` 时若仍有调用，先按取消返回契约清理并标记失败，不提交候选输出。
- invocation 的 Drop 统一执行正常取消返回；不强制 unwind/reset。借用 handle 被丢弃仍终止原实例，owned task 被丢弃则清理后销毁实例。违反取消契约的可信代码仍触发 OS 进程终止。

## 验证

受限子进程在 debug/release 验证：未启动和挂起任务移动、共享模块多任务交错、忙时拒绝、零时间片、不重放、成功后下一条调用、池耗尽不毒化实例、跨模块 ID 拒绝、取消与预算失败、完成立即释放栈，以及丢弃/取回未完成任务的清理。已有活栈与直接调用回归必须保持通过。两平台分别运行 CI，不能以本机结果代替。

## 影响与边界

不改变 ABI v3、业务状态布局、生成代码和资源账户协议，不引入共享可变业务数据。新增槽位仍未接入三级计费；它只是后续进程表的所有权边界，不能据此宣称 mailbox、公平调度、根链、GC 或 M0 已完成。编译器栈限额与精确根仍是开放控制流和业务堆的前置条件。

替代方案是自引用进程表或每个实例固定地址分配；前者增加不安全证明负担，后者增加间接访问且仍需执行权协议。本切片选择不借用实例的 invocation。未来跨 worker 迁移必须独立定义根链、线程本地状态和唯一执行权协议，不能直接添加 unsafe Send。
