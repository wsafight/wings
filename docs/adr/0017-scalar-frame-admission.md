# ADR-0017：标量 AOT 的编译帧准入

- 日期：2026-11-12
- 状态：已采纳（M0 有界标量切片）
- 补充：[标量 AOT](0009-scalar-aot-prototype.md)、[有界栈池](0012-bounded-stack-pool.md)

## 背景与决定

有界栈池限制可用容量，但 IR 操作数上限并不直接证明寄存器溢出后的机器栈帧大小。先在当前无递归、无业务函数调用的直线标量子集中，检查后端实际生成的帧；不以 guard page 代替编译准入。

- 后端完成机器码生成后、写入任何产物前，读取 Cranelift 0.118 的 `CompiledCode::frame_size`。initializer 与每个 handler 都必须不大于默认 64 KiB 的编译帧限额，否则构建失败，输出目录不创建。
- `build` 使用默认限额；库调用 `build_with_frame_limit` 可指定更小的非零限额，但不得提高到 64 KiB 以上。参数无效或某个入口超限都在链接和写目录前拒绝。
- 该数字覆盖 spill、局部栈存储与被破坏的 callee-saved 寄存器保存，不覆盖 ABI setup、临时压栈、宿主协程包装、慢路径及运行时 Rust 调用链。当前所有受管入口均为叶子，唯一间接调用是固定的可信让出回调；不把 64 KiB 视为整个 256 KiB 栈成本或完整运行时栈安全证明。
- 不改变 ABI v3、产物字段、取消优先级或执行步数。清单仍不能证明任意机器码安全；装载接口继续只接受可信编译产物，不靠清单中自报的帧尺寸信任不可信库。

## 验证与边界

受限子进程在 debug/release 构建正常 Counter、48 活跃标量和更高寄存器压力的程序；限额为 1 字节时须在写目录前明确拒绝，零限额与高于硬上限的配置也须拒绝。正常产物继续通过原栈恢复、预算与失败提交回归。macOS AArch64 与 Linux x86-64 分别执行，不将一个平台的帧尺寸外推到另一个平台。

此切片只是静态编译帧准入，不是动态剩余栈检查或受管 `stack_overflow`。开放函数、递归、循环中的调用、alloca 或更长内建前，必须定义并验证调用前剩余容量检查、最大不可抢占区段及慢路径保留空间；不能因为静态帧不超限就直接开放。精确根与 shadow stack 仍未实现，M0 仍未完成。

替代方案是仅依赖 IR 指令数或未知 SIGSEGV；前者与后端 spill 不等价，后者不能局部恢复。选择当前可验证的静态准入，未来动态调用另设 ABI 决策，而不是使用后端 trap 跨越受管错误返回契约。
