# ADR-0018：有界不可变记录堆与显式根帧

- 日期：2026-11-12
- 状态：已采纳（受管堆独立原型，尚未接入 AOT）
- 相关决定：[精确根与非移动 GC](0004-safepoints-and-gc.md)、[三级账户](0014-resource-reservations.md)

## 背景与决定

先验证业务引用的身份、布局、根和回收，再向语言开放堆值。当前标量 ABI 没有引用，不能用标量活栈恢复代替根完整性验证。

- VM 内增加单线程 `RecordHeap`，只保存不可变、最多 8 字段的定长记录。每个堆最多 1024 槽及 128 个布局，构造时固定全部容量，运行中不增长。布局按字段区分 Int、Bool、Unit、本堆引用；payload 使用无动态标签的 64-bit 字段，按布局精确识别引用，不猜测整数位型。
- 外部 `HeapRef` 带堆身份、槽号和 generation；读取、根发布和构造记录检查归属，复用槽位递增代次，耗尽的槽位退休。记录内部只保存本堆槽号和代次，不能跨进程共享可变数据或把裸指针作为消息引用。
- 分配先完整验证布局、字段数、类型和引用，再占用槽位；失败不改变堆。不自动收集，满时返回明确错误。此为底层原语，未来语言分配慢路径仍须从全部根尝试本地 GC，再决定 `heap_overflow`。
- `ShadowRoots` 固定最多 64 个根槽，绑定同一堆。借用式 `RootFrame` 以 LIFO 方式发布、替换根，Drop 截断该帧；嵌套帧不能越权替换父帧根。帧不持有可变堆借用，可在发布根期间继续分配和触发回收。根槽持有 handle，不保守扫描原生栈。
- 收集先检查全部根身份与代次，再从显式根精确 mark-sweep；标记工作表预分配，每个对象只入表一次，返回后不移动活对象。根无效时不回收、不改变收集计数。最坏扫描工作由对象数 × 8 字段及根上限限定；未承诺 GC 延迟目标。
- 每次收集只接受一个显式根表，必须由调用者包含全部存活根；宿主保存的 handle 和其他根表不自动保活。漏发布导致的 stale handle 会明确拒绝，不能据此声称编译器根完整性已经验证。
- 堆、布局表、标记工作表和根表在申请存储前向 process 账户预留所请求的容量字节及控制结构成本，票据与存储同寿命；构造失败回滚。此处计费为 Rust 请求的存储容量，不是 allocator 内部开销、RSS 或 OS 隔离；共享账户节点和其他运行时资源尚未全部接入。

## 验证与边界

受限子进程在 debug/release 验证四类字段、schema 拒绝、跨堆引用、stale handle、槽位复用、不可变记录图保活、整数位型不误认根、嵌套根帧与作用域清理、根容量、非法根导致零回收、满堆先拒绝后收集复用，以及三级分别拒绝和 Drop 归零。没有真实 OOM/非法访存注入，不在宿主制造资源耗尽。

本切片不改变 ABI v3，不增加语言记录语法或 compiler 根发布，不在 AOT safepoint 执行 GC；固定槽不是最终 arena/slab 分配策略，空闲槽仍保留容量并计费。精确根进入生成代码、状态/消息/回复根的完整性、动态栈检查、worker 和 BEAM 等价负载仍为后续门槛，不宣称 M0/M1 完成或内存领先。

替代方案是先开放引用而暂不回收，或保守扫描栈；前者掩盖根遗漏，后者违反精确根约束。先实现可验证的布局与根原语，再按独立 ABI 决策连接编译器。将来加入变长字符串、跨进程复制或迁移前，必须补齐容量/临时缓冲计费、所有权和根发布协议。
