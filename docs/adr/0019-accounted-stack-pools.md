# ADR-0019：栈池容量与活栈的净计费转移

- 日期：2026-11-12
- 状态：已采纳（单线程栈池接入契约）
- 补充：[有界栈池](0012-bounded-stack-pool.md)、[资源预留](0014-resource-reservations.md)

## 背景与决定

仅限制栈池槽数不能防止租户建多个池绕过 VM 上限；只给活栈计费又会漏掉缓存和元数据。先把池容量作为租户承诺预留，再把借出的槽位额度净转移到进程。

- 保留未计费的宿主探测接口 `StackPool::new`，新增 `new_accounted` 接受 tenant 账户。它在创建向量和 mmap 前预留全部槽位（可用容量加 guard 页）以及请求的控制结构、槽索引和票据表容量。失败释放已完成的预留，不留下映射或部分账目。
- 计费池必须先 `for_process` 绑定其租户下的 process 账户，再用于已有 `start_in_pool` 或 owned task。原计费池直接借出、其他租户或非进程账户一律拒绝；不把传入了一个任意账户视为合法所有权。
- 借出槽位时，把这一槽的票据从 tenant 净转移到 process；共有 tenant/VM 额度不变。目标 process 不足时，不弹出槽、不激活页、不终止实例。激活失败则把票据转回租户并保持槽位可用。
- 完成或正常取消后先正常退出活栈，再把票据转回 tenant；缓存、未激活空槽与 guard 地址仍由池计费。`trim` 释放物理页但不释放容量承诺，因此账目不下降。最后一个池/活栈 owner 释放后 unmap 并归还全部池额度。
- `stats.charged_bytes` 报告池总预留（活栈已转移部分也计入），未计费池为零；这是容量准入，不是 RSS。固定 guard 和未触碰容量的保守计费有意避免过度承诺，不把预留字节误报为已驻留内存。

## 验证与边界

受限 debug/release 子进程验证三级拒绝、租户/VM 满额时仍可净转移、进程不足不激活、不毒化实例、完成/Drop/取消归还、缓存及 trim 不逃逸计费、错误租户拒绝、池先于活栈释放和最终归零。已有未计费栈池及原栈恢复回归保持通过，双平台分别执行。

此切片不计入 scalar task 头、参数 Vec、token 或模块全部成本，不是完整进程准入；默认 TLS 池仍是宿主调试便利路径。调度器必须只用显式计费池，并把其他增长资源逐项接入。仍不支持 M:N，不能给 Rc/Cell 直接添加 Send/Sync。
