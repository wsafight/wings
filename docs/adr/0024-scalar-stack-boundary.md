# ADR-0024：标量入口的剩余栈检查

- 日期：2026-11-12
- 状态：已采纳（M0 有界标量切片）
- 补充：[ADR-0017](0017-scalar-frame-admission.md) 的静态编译帧准入
- 替代：[ADR-0011](0011-scalar-stackful-resume.md) 的 context 布局及同步调用使用宿主栈的安排
- 后续：[ADR-0025](0025-aot-record-roots.md) 扩展为 ABI v5，保留本文栈边界，增加临时记录与 compiler 根链。

## 背景

静态帧上限不能说明调用位置还剩多少栈。将检查放进业务函数正文也太晚：后端 prologue 已经分配该函数的 spill frame，可能先触碰 guard page。当前没有业务函数调用或递归，先限定所有 initializer/handler 的入口边界，不借此开放控制流。

## 决定

- 未发布源码升级为标量 ABI v4，在 context 末尾增加 `stack_limit: usize`，表示本次执行不能向下越过的栈地址。增加 `STATUS_STACK_EXHAUSTED = 6`；旧 v1/v2/v3 清单在装载共享库前拒绝。已发布包不变。
- initializer 与 handler 的导出符号是薄入口，实际业务函数为本地符号。先读取当前 SP，拒绝零限额、SP 低于限额，或剩余空间不足“实际业务编译帧 + 4 KiB ABI 余量”，再调用业务函数。薄入口自身的后端帧不得大于 4 KiB，超限在写产物前拒绝；业务帧继续受默认 64 KiB 静态上限约束。
- 所有 VM 业务入口，包括同步 `invoke`、CLI 与 initializer，都使用同一有界池的 256 KiB 可用栈，不再借用未知剩余空间的宿主线程栈。context 限额设为 guard page 上沿再加 64 KiB，留给固定可信慢路径。入口检查失败不消耗步数、不调用慢路径、不写输出，按受管失败结束实例；栈不足优先于业务帧内取消/预算检查。
- 同步入口的池获取或参数准备失败属于执行前拒绝，不终止已有实例。已经进入的调用仍按正常返回提交，或失败终结；挂起调用仍以正常取消返回释放，不跨 ABI unwind。同步调用与挂起调用共享每线程默认池的容量，池满时显式失败。
- `ScalarModule::instantiate_in_pool` 允许显式初始化池；worker 必须使用绑定进程账户的计费池，初始化不足栈额度时立即拒绝并回滚 spawn，不延迟到第一条消息。初始化后归还栈；后续排队消息或请求持有额度仍可能使 handler 的栈准入失败，失败保留原队列与状态。

## 验证与边界

Rust 回归锁定 context 布局、状态码、旧 ABI 拒绝及 guard/限额地址关系。受限 OS 子进程对真实 AOT 的 initializer 和 handler 注入零、过高及可用限额，检查错误码、零扣步、候选输出不变和慢路径不调用；高寄存器压力与原栈恢复回归继续执行。debug/release、macOS AArch64 与 Linux x86-64 各自验证，不在开发宿主故意耗尽原生栈。

4 KiB ABI 余量与 64 KiB 慢路径预留是当前可信、无递归标量路径的保守工程界限，不是任意 Rust 调用链的形式化上界。薄入口自身 prologue 要求调用方已留出其空间；后续开放业务函数、递归或分块内建前，须增加调用点准入及慢路径栈上界验证。本切片不实现 compiler 根链、业务 GC、M:N 或完整动态调用深度控制，不宣称 M0/MVP 完成。

## 替代方案与重审条件

- 只保留静态帧上限或 guard page：无法在业务帧分配前返回受管错误。
- 直接使用后端 stack-limit trap：需要另外证明 trap 捕获与清理，不符合当前正常返回、不 unwind 的 ABI。
- 在宿主栈查询平台线程边界：继续混用两种栈与慢路径前提；先统一到已有池，不新增平台依赖。

后续引入业务调用、改变后端 prologue、慢路径深度或栈大小时重审余量与检查位置；同步入口新增栈切换成本须单独测量，不把功能边界改进描述成性能提升。
