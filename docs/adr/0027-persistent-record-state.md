# ADR-0027：持久记录状态与提交根

- 日期：2026-11-13
- 状态：已采纳（M0/M1 有界持久状态切片）
- 补充：[ADR-0025](0025-aot-record-roots.md)、[ADR-0026](0026-language-temporary-records.md)
- 替代：上述记录中禁止 Ref 状态的限制；消息与回复仍只允许标量

## 背景与决定

临时记录不能表示跨消息保留的业务数据。先开放单个 `RecordInt` 状态，不同时开放引用消息、通用 schema 或跨进程 handle。

- 语言 state 可声明 `RecordInt`，initializer 必须产生同类型值；赋值只替换不可变记录绑定。参数与回复仍拒绝 RecordInt，外部 JSONL 不接受 handle。
- ABI 升至 v6，context 布局不变，但清单允许 Ref 状态。旧 v1–v5 产物在装载原生库前拒绝，避免旧运行时把状态编码当普通整数。`ValueType::accepts` 仍不能验证 Ref，必须由所属堆验证 slot/generation、存活与记录字段。
- Ref 状态要求显式计费堆；无堆初始化在执行 initializer 前拒绝。成功初始化验证返回引用后建立宿主持久根。空闲时持久根与堆同寿命；运行时堆连同持久根移入原协程。
- 每次 GC 合并一个已提交状态根和最多 64 个 compiler 根，完整验证后才回收。持久根在 handler 完成前始终指向旧状态，即使生成代码已不再读取它；候选引用由编译器保活到成功出口（包括最后检查点）。initializer 的候选也遵守该规则。不把整数位型猜为根。
- 正常返回后先检查状态和回复，再替换持久根及状态绑定；无 GC 或其他可失败操作夹在两者之间。失败、取消、预算耗尽、堆满和丢弃挂起调用不提交候选，保持原有失败退出契约。旧记录在后续 GC 才可回收，因此二槽堆能反复替换，单槽堆替换必须显式堆满而不能提前释放已提交状态。
- 宿主 `committed_state` 诊断只返回标量，Ref 状态明确报错而不泄漏 handle；业务通过 `read_int(state)` 回复 Int。worker 继续显式 `spawn_with_heap`；默认监督接口无堆，拒绝该模块，不静默选择额度。

## 验证

前端/LSP/IR/清单验证 state 类型、赋值与消息边界；根活跃度覆盖仅作返回状态、尾检查点、64 根极限及初始化。真实 AOT 在受限 OS 子进程验证初始化、跨消息 GC/槽复用、候选提交前收集、逐步暂停/恢复、多 actor 隔离、单槽拒绝、失败不提交与账户归零。Rust 测试验证无效/stale 输出拒绝、持久根与编译器根合并、整链无效时零回收及初始化无堆拒绝不执行。编码不含堆身份，不能证明任意可信 native 返回编码的来源；仍禁止跨堆传递或安全反序列化，不能将验证当作 native 沙箱。

debug/release、MSRV、macOS AArch64/Linux x86-64 分别验证。仍未覆盖引用消息、字符串、业务控制流、语言消息副作用、M:N、真实 I/O 或同业务 BEAM 双目标，不宣布 M0/MVP 完成。

## 替代方案与重审条件

- 不选在入口临时读取旧状态来保活：SSA 死值分析可能提前移除它，无法维护失败不提交契约。
- 不选提前释放旧状态给候选让槽：失败路径会留下 dangling committed state。
- 不选所有历史引用永久保活：有界堆将无法复用槽位。
- 通用记录 schema、多状态、引用消息或移动 GC 会改变验证与根布局，须另立 ADR 和故障回归。
