# ADR-0028：带堆进程的受控重建

- 日期：2026-11-13
- 状态：已采纳（M1/M4 宿主恢复集成切片）
- 补充：[ADR-0023](0023-bounded-host-supervision.md)、[ADR-0027](0027-persistent-record-state.md)

## 背景与决定

RecordInt 状态已可跨消息存活，但监督默认不配置堆，无法重建这类进程。增加显式入口，不自动推测容量或继承旧实例内存。

- `ScalarSupervisor::spawn_with_heap` 接受与 worker 相同的记录槽数及已有重启策略；普通 `spawn` 继续无堆。子项保存 `Option<usize>` 堆配置，槽表计费包含该字段。首次创建与每次重建均调用同一 worker 准入路径，以相同模块、process 限额、mailbox 容量及堆容量重新初始化。
- 旧实例在新实例创建前先正常取消/退出，释放活栈、堆、持久根与消息，旧请求按原 ID 终结。新堆不复用旧 handle，不迁移已提交或候选状态，不重放消息；同一 ChildId 只更新到新 generation Pid。
- 堆配置/额度/初始化拒绝必须回滚本次全部预留。重建失败保留原退出原因并报告 `RestartStatus::Failed`，移除子项，不在后续 tick 重试；强度、Never、stop/Drop 和 sibling 行为不变。
- 标量诊断仍不暴露 Ref 状态编码；通过业务 Get 请求验证新状态。此接口仅宿主 one-for-one，不新增语言监督、持久化、状态恢复、热更新或跨线程共享。

## 验证与影响

Rust 回归覆盖无堆拒绝、非法堆容量、三级额度不足、首次/重建初始化失败、旧状态根释放及账户守恒。真实源码 AOT 在受限 debug/release 子进程验证有状态进程重新初始化、两次重启后强度耗尽、旧请求终结、无重放、sibling 状态及挂起 stop 清理。macOS AArch64/Linux x86-64 分别验证，不把宿主恢复等同 MVP 或 BEAM 性能门禁。

沿用现有模块、资源账户与 worker，不增加依赖或 ABI 版本；ABI v6 的状态/消息边界不变。未来扩展通用值、可配置堆布局或恢复策略时重新评估子项配置和迁移语义。

## 替代方案

- 不默认给所有子项开堆，避免隐式容量和内存承诺。
- 不保留旧堆给新实例：那会改变“全新 initializer”恢复契约并保留失败对象。
- 不在重建失败时无限重试，保持有界工作和原始诊断。
