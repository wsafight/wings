## 背景与决定

直线入口无法按输入选择业务结果。先开放无回边的条件表达式，验证未选分支不执行、路径检查点与根发布，再独立设计循环和业务函数。

- 新语法 `if condition { expression } else { expression }`：条件必须 Bool，两臂必须同一标量类型 Int/Bool/Unit；显式 else 必需。每臂暂只含单个表达式，不支持臂内 let、赋值、声明或 RecordInt 结果。可嵌套、作为 initializer/局部/状态赋值/回复或内建参数；只执行被选中的一臂，不把两臂预先求值为 select。
- 该切片暂以现有 Bool 字面量、参数或状态作为条件，不同时添加比较运算、循环或任意函数。可在选中臂使用现有受限内建，包括创建并读取临时记录；记录结果必须在臂内消费为标量。
- IR 使用结构化 If/Else/EndIf 标记，无任意跳转。验证最多 64 层、完整配对、Bool 条件、标量合流与分支作用域；另一臂和臂后的代码不能引用分支内部寄存器。未配对、越界、前向和跨臂引用在写产物前拒绝。
- Cranelift 将两臂降为真实控制流和带类型块参数的标量合流。每个实际执行的 IR 标记/操作及最终提交前保留强制取消/预算/让出检查，未执行分支不扣步、不分配、不失败；预算按实际路径而非源码总操作数计费。栈帧仍按后端实际最大帧准入。
- compiler 对根采用保守的直线最后使用计划：分支外引用可在未使用它的臂暂时多保活，但不能发布另一臂才定义的引用；臂内引用在臂结束前消费。候选 Ref 状态仍由外层根保活至出口，宿主持久根不变。每函数至多 64 根，超限拒绝；不宣称路径最优根数量。
- ABI v6、清单与消息协议不变；现有直线产物兼容。未来开放引用合流、臂内状态赋值、循环或函数时须重审 CFG 活跃度与根计划，不能直接沿用该受限证明。

## 验证

前端/LSP 验证不完整/嵌套语法、Bool 条件、臂类型、标量限制与节点上限；IR 验证结构、深度和寄存器支配。真实 AOT 受限子进程验证两方向、嵌套、未选除零/溢出/无堆分配不发生、所选失败不提交、实际路径预算、逐步恢复、记录根和最终出口。debug/release、MSRV、两个首要平台分别验证，不把无回边分支当成完整 M0 或公平调度验收。

## 替代方案

- 不用 eager select：会执行未选臂的分配和失败，改变语言语义。
- 不在本轮引入任意 CFG、引用 phi 或完整语句块，避免未验证的根和候选状态合流。
- 不为抢占跳过分支或合流处检查；以后仅可在完整检查覆盖证明与回归下优化。
