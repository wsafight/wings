# ADR-0030：标量比较与条件输入

- 日期：2026-11-13
- 状态：已采纳（M0 表达式切片）
- 补充：[ADR-0029](0029-scalar-conditional-expressions.md)

## 背景与决定

已有 if 只能使用现成 Bool，需比较业务输入后才能选择有意义的处理路径。

- 增加 `==`、`!=`，接受同类型 Int/Bool/Unit；增加 `<`、`<=`、`>`、`>=`，仅接受 Int，使用有符号 i64 顺序，结果为规范 Bool（0/1）。不比较 RecordInt handle，不提供隐式转换或对象身份相等。
- 比较低于加减乘除与取负的优先级，比较之间从左到右结合；不提供数学式链式比较，`1 < 2 < 3` 因 Bool/Int 不匹配而拒绝。两侧从左到右各求值一次；比较不溢出、不通过相减实现顺序。
- 源码/语义/IR/Cranelift 使用显式比较操作，检查操作数类型及分支作用域。每条比较仍有取消/预算/让出检查，根计划计入两侧操作数，ABI v6 不变。无循环、短路逻辑或函数扩展。

## 验证与边界

验证词法 longest-match、优先级、错误类型、未完成编辑、i64 两端/相等/反序、Bool/Unit 相等、比较结果驱动 if、记录读取后比较及预算扣步。真实原生行为按既有受限 OS 子进程执行 debug/release、双平台和 MSRV，不能当作完整控制流或性能验收。

不采用减法比较以避免边界溢出，不通过外部宿主提前求值；未来通用值相等与短路逻辑须单独规定成本及失败顺序。
