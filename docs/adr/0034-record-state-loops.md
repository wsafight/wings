# ADR-0034：RecordInt 状态回边与出口根

- 日期：2026-11-13
- 状态：已采纳（M0 引用回边切片）
- 替代：[ADR-0031](0031-scalar-state-loops.md) 的“while 仅支持标量 state”限制；补充 [ADR-0033](0033-record-conditional-roots.md) 的结构化路径根。

## 决定与理由

RecordInt 状态已能持久提交和条件选择，循环仍拒绝该状态使连续业务更新无法验证。不能只放宽类型：循环头当前引用、零次迭代出口和回边候选都需要不同的根边界。

- handler 的 while 可携带唯一 RecordInt state，保持不可变记录和仅替换 state 的约束。条件仍 Bool、体仍 Unit、let 不可变且体内绑定不逃逸；不增加可变局部、引用消息、break/continue 或任意 CFG。
- Loop header 的块参数在任何检查之前发布为当前引用根；即使条件不读取 state，也至少保活至 While 分派，因为假路径要以当前值退出。回边把下一候选传入同一个 header 参数，每轮重新发布，不重放已执行操作。
- 只用于初次进入循环的旧引用在跳转到 header 后不再发布；它可能已在后续迭代被收集。外层仍会再次使用的引用按原有循环范围延长规则保活，不把“初始引用”和“本轮引用”混同。
- EndLoop 的检查发生在回边之前，保活回边候选；假路径不执行该检查。after 块取得当前 header 引用作为 EndLoop 结果，下一次检查只发布循环进入前仍活跃的外层引用和出口值，不发布仅在体内定义的寄存器。零次迭代同样适用。
- 已提交状态由宿主持久根独立保活，所有迭代仅替换候选；正常返回及输出验证后才提交。预算、取消、算术/堆错误保留旧提交，不成功回复；原栈恢复/Drop 清理契约不变。长循环需要容量容纳旧提交、当前候选及下一候选，不能承诺两槽始终足够。
- 根槽容量包含 header 和出口的实际检查位置，64 根/控制层、4096 操作、1024 堆槽与固定执行栈继续有效。ABI v6 与 runtime 根协议不变，不增加后台 GC 或关闭回边检查。

## 验证与重审

前端/LSP/lower/IR 检查 RecordInt state、回边类型、跨体逃逸、零次/嵌套路径和根容量。受限原生子进程每次慢路径/内建前收集，验证未读 state 的条件、每轮新候选、旧外层别名、嵌套条件/循环和出口；runtime 用小堆逐片恢复、取消/预算/算术失败、正常提交及额度归还。debug/release、MSRV 和双平台独立验证，Linux x86-64 结果未取得前不记通过。

不采用循环展开、保留所有历史候选或禁用 GC；引用布局仍只单 Int 字段。任意引用 phi、函数调用、多 state 或移动 GC 须另立证明，不把该切片视为完整 M0/MVP 或性能结果。
