# ADR-0036：有界非递归业务函数与内联根

- 日期：2026-11-13
- 状态：已采纳（M0 源码函数切片）
- 后端决定由 [ADR-0042](0042-managed-function-frames.md) 的有界受管调用帧替代；以下保留原内联理由。
- 补充：[ADR-0002](0002-language-and-aot.md)、[ADR-0025](0025-aot-record-roots.md)、[ADR-0033](0033-record-conditional-roots.md)

## 决定与理由

先交付可复用业务表达式，不立即引入递归、动态 dispatch 或新的受管调用 ABI。每次静态调用内联到已有结构化 IR，复用已验证的精确根、预算和实际帧准入；该能力不等于跨帧根链与动态调用栈已验证。

- process 内声明 `fn name(arg: Type, ...) -> Type { statements; expression }`，参数和返回类型必填；可用 Int/Bool/Unit/RecordInt。最多 64 个函数、每函数 64 个参数，函数名不与内建重名。同 process 的 handler 和 state 默认值可调用这些函数。
- 函数只访问参数、不可变 let、内建及声明顺序中更早的函数，不隐式访问/替换 process state。禁止直接/间接递归、前向函数调用、while、消息副作用和函数值；最长静态函数链 32 层。参数/局部可遮蔽函数名，但遮蔽后的绑定不可调用。
- 实参严格从左到右且每个只求值一次，进入函数时建立独立局部绑定，结束后恢复调用者绑定；内联不会把函数局部名称泄漏给调用者。函数可以构造/返回当前堆的记录和触发 collect，错误直接终止当前 handler，不提交候选 state；初始化错误仍拒绝创建实例。
- 展开后的每入口仍最多 4096 IR 操作，嵌套控制最多 64 层、活跃根最多 64、实际后端帧最多 64 KiB；展开发生前检查链深，每次 push 检查操作数，不先建立无界展开树。参数引用和返回记录成为同函数 SSA，活跃度/root 规则与普通表达式一致，合流前仍发布引用。
- 每次内联函数入口生成一个带检查的 Unit 标记；即使函数只返回参数、没有计算，也消耗操作/运行步数，不能通过倍增的空调用绕过展开上限。实参求值在该标记之前，标记不公开为业务结果。
- lower 额外限制展开后表达式递归深度为 256；每个独立源码表达式都符合解析上限，不代表多层函数展开后的编译器调用栈安全。超过时在继续递归前拒绝构建，不在编译宿主触发栈溢出。
- ABI v6、产物清单、装载和运行时无变化。函数不导出原生符号，不允许宿主直接调用，不暗示任意 Rust 函数可进入受管路径。LSP 与编译器共用解析/类型/定义引用，不依赖 VM 或 codegen。

## 验证与重审

前端验证签名、恢复、数量/参数/深度、缺失/多余参数、顺序、遮蔽、状态隔离、禁止循环/递归及参数不可变；LSP 校验 hover/定义/补全。lower 验证单次实参求值、独立绑定、类型根、展开操作上限。受限原生子进程验证 checked 算术、惰性条件、RecordInt 参数/返回、调用中 collect 与循环内调用、逐片恢复/预算/取消、失败不提交、计费清理。debug/release、MSRV 和两个首要平台独立验证。

拒绝“无界递归后靠 native stack overflow 退出”和“完全内联即没有栈成本”的说法。需要递归、动态调用或降低重复代码时另立受管函数 ABI、调用帧栈检查、跨帧精确根和预算证明，不把本切片当完整 M0/MVP 或性能领先证据。
