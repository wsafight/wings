# ADR-0044：原生模块租约与加载准入

- 日期：2026-11-13
- 状态：已采纳（M1 模块资源切片）
- 替代：[ADR-0013](0013-shared-scalar-modules.md) 的共享库永久泄留决定
- 后续：[ADR-0045](0045-concurrent-resource-admission.md) 将资源账户改为线程安全；本决定的模块 Rc 租约和原线程执行限制保持不变。
- 后续：[ADR-0052](0052-cross-thread-module-leases.md) 将只读模块租约改为 Arc，允许不同 worker 线程中的独立进程共享代码；actor/活栈仍不迁移。
- 后续：[ADR-0081](0081-accounted-default-cli.md) 将 CLI 默认标量模式改用计费加载，独立库工具入口仍保留。
- 后续：[ADR-0083](0083-accounted-module-execution.md) 要求计费模块所有执行路径使用本 VM 的 process 计费池，禁止通过未计费池绕过执行准入。
- 后续：[ADR-0084](0084-accounted-root-module-admission.md) 同时禁止未计费工具模块接入计费根，工具加载不能绕过该根的模块预算。
- 后续：[ADR-0085](0085-module-path-admission.md) 将原控制预算提前到路径解析之前，库页随后追加，同一租约持有且总额不变。

## 决定与理由

原型遗忘 Library 会在反复加载后永久保留映射，且无法随资源释放归还预算。改为最后一个代码所有者释放后销毁 Library；这仅适用于匹配本编译器的可信、无自注册回调/后台线程/原生析构副作用的静态 AOT 模块，不提供运行中热更新、版本迁移或任意 native 扩展卸载。

- ModuleData 直接持有 Library，ScalarModule、HandlerId、实例及活栈执行所有者都保留共享代码租约。Drop 挂起入口先正常取消逐层返回，再释放模块。最后一个所有者消失才交还动态装载器引用；不声称 OS 一定立即解除所有页映射。
- 新 `ScalarModule::load_accounted(directory, vm)` 只接受 VM 账户，在读取清单、解析符号或加载 native 代码前预留按 4096 字节向上取整的库文件大小加 2 MiB 控制预算。预算覆盖有界 manifest/元数据/符号表及临时校验缓冲的保守用户态逻辑容量，不是映射段、dyld/ld.so 内部开销或 RSS 精确计量。已有清单 64 KiB、库 64 MiB 上限不变。
- 同模块 clone、ID、实例共享一次预留，不重复计费。最后一个租约在 Library 交还后释放预算；加载/符号/校验/分配失败归还预留，不产生常驻半模块。分别加载同一路径各自预留，不以动态装载器可能共享映射为理由省略准入。
- 计费模块绑定 VM 身份；跨 VM worker 或带堆实例在分配/执行 initializer 前拒绝。账户目前单线程，因此计费租约不能跨线程；不提前宣称支持 M:N。旧 `load_trusted` 仍为明确不计费的工具/可信原型入口，也改用代码租约，不把其兼容性当完整资源门禁。
- 可信路径和产物在校验至加载期间不得被修改；不是抗竞态的不可信文件沙箱。两加载函数均 unsafe，调用者保证原生 ABI、根、预算及库生命周期约束。

## 验证与重审

受限真实 AOT 子进程覆盖加载额度/账户级别拒绝、坏清单/库/缺符号回滚、共享一次预留、最后一个 HandlerId/实例/挂起执行保活、Drop 顺序、反复加载释放与跨 VM 拒绝。检查活栈取消完成后再释放预算，所有资源回到基线；两平台 debug/release、MSRV 独立验证。

这是有界逻辑模块预算与生命周期修复，仍未覆盖全部 allocator/动态装载器/平台映射元数据。完整 M1、热更新、并发账户和双平台 BEAM 内存门禁未完成。引入原生析构、自注册函数、外部回调、后台线程或跨 worker 调用前必须重审代码静止期，不沿用当前最后引用销毁假设。
