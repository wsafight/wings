# ADR-0045：跨线程三级资源准入与净转移

- 日期：2026-11-13
- 状态：已采纳（M:N 资源前置切片）
- 替代：[ADR-0014](0014-resource-reservations.md) 的同线程账户限制
- 子账户控制节点的计费入口与生命周期由 [ADR-0050](0050-account-node-admission.md) 扩展；以下保留原决定。

## 决定与理由

外部有界 inbox 和后续多 worker 必须共用同一个 VM 的资源上限，不能各在线程本地检查后累加。先提供可证明的串行提交协议，不以单独四项原子加减代替多维、多层原子准入。

- ResourceAccount 使用 Arc 持有不可变层级、上限及四项原子计数。每个 VM 创建一个共享 Mutex 门闩，同 VM 的 reserve、transfer、Drop 与 used 都通过该门闩；其他 VM 不互相阻塞。计数的 relaxed 访问只在门闩内进行，used 返回单账户四维一致快照，不承诺连续查询多个账户的整体快照。
- reserve 先校验最多三级、四维的全部溢出与额度，再无分配地提交；失败零变化。transfer 只接受同 VM，最多五个不同账户，共同祖先不增不减；先校验目标独有路径，再增加目标、归还源，禁止临时双计共同祖先。票据不可克隆，跨线程移动后仍由唯一所有者归还。
- 不在门闩内执行 allocator、业务回调、OS 等待、协程切换或构造错误字符串；检查失败在释放锁后格式化。已校验提交只做固定长度计数写入，无用户可注入的 panic。内部锁中毒时恢复门闩，不跳过准入或资源归还；不允许外部代码取得锁。
- ResourceAccount 与 Reservation 可自动 Send/Sync，不添加 unsafe Send/Sync。actor、堆执行权和 guarded stack 仍受原 Rc/线程绑定约束；不会因为账本可并发就允许迁移活栈或并发运行同一 actor。代码模块的 Rc 租约暂不改变。
- VM 级共享锁可能成为吞吐瓶颈，是当前正确性基线，不宣称无锁或领先 BEAM。后续按同业务数据测争用再讨论分片/批量额度租约；不得移除三级限额、失败回滚或共同祖先净转移。

## 验证与重审

保留独立模型的单线程四维/三级/溢出/转移回归。新增屏障驱动的多线程测试：每维每层争抢固定额度、同级/跨租户迁移、满共同祖先净转移、失败无泄漏、票据跨线程归还、账户 handle 提前释放、四维快照一致及不同 VM 隔离。工作线程和轮数有固定上限，无 OOM 或崩溃注入。

执行 workspace check/test/clippy/fmt、MSRV 及 debug/release 受限 AOT 回归；两首要平台独立验收。此切片不是有界 inbox、M:N 调度器、迁移或完整 M1；账户/allocator 控制元数据、外部 I/O 与双平台 BEAM 门禁仍须完成。

2026-11-13 在 macOS AArch64 通过上述 workspace 检查、Rust 1.85.0 all-targets 检查及 debug/release workspace 测试和受限 AOT 回归；Linux x86-64 尚未验证此切片，没有双平台通过或争用性能结论。
