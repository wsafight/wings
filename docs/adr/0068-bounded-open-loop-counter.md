# ADR-0068：计划时刻驱动的短时开环 Counter

- 日期：2026-11-14
- 状态：已采纳（开环正确性前置，不是性能验收）
- 扩展：[ADR-0067](0067-beam-bounded-admission.md)
- 协议：[BEAM 工作负载](../beam-workloads.md)

## 背景与决定

闭环窗口会掩盖过载，不能作为固定到达速率的替代。先用同一单调时钟计划，把四组非 fairness 代表负载接入真实 Wings Scheduler 和 BEAM actor；不改 ABI、业务语法或原有正确性测试限制。新增 v5 短时开环入口，明确标记 `smoke`，不输出吞吐排名或宣称尾延迟达标。

actor 数、前 100 个活动集合、完整 Bytes/binary 状态、mailbox 1/100 和热点路由沿已冻结表。每次请求 checked +1，逻辑请求/成功回复仍为 32 B。一个真实发送者直接投递，不经代理。BEAM 使用已验证的发送前 CAS gate。开始业务前确认所有 actor 初始化完毕。

第 k 次到达固定为 `t0 + floor(k*10^9/rate)`，k 从零开始；总次数为 `ceil(rate*duration_ms/1000)`。生成器每轮先有界收集，再尝试下一条到期请求，不等待旧请求完成，不暂停计划、不跳过迟发请求、不重试拒绝。驱动空闲时 yield；该驱动 CPU 和存储成本将来必须计入整机测量，不能只量业务线程。

每轮收集最多 32 条结果；Wings 在固定 pending 中轮转探测至多 32 个票据，不每次到达都全扫 256 个带锁票据。BEAM 每轮直接取至多 32 条到达结果，不以选择性接收掩盖同目标乱序。轮转不保证跨 actor 观察全序，也不承诺与 BEAM 相同的采样成本。

驱动最多保留 256 条尚未收到真实结果的 pending，包括已经超时的请求。满时本次到达记录 `pending_full`，不能等待空位后补发。mailbox 满单列 `mailbox_full`，不当作已接受。原始样本最多 10000 条、持续时间 1..1000ms、速率 1..1280000/s，超出在加载 artifact 或启动 actor 前拒绝。此限制是短时验证边界，不缩小未来 30s/60s/五次重复的性能验收。

## 端到端截止时间和结果

每条已接受请求的外部 deadline 为计划时刻后 100ms，而不是实际发送后。终态以驱动观察时刻判定：截止前观察为 `reply`；截止时未观察为 `timed_out`，迟到回复只能补充实际值与观察时间，不能改写超时终态。采样时刻在读取结果之后取得，包含收集器成本。超时不取消远端业务，也不撤回已发生的提交；驱动持有原 pending 至实际回复，避免把超时当成无限复用空间。

Wings 内部请求租约使用整个受限业务阶段的剩余时间，而非外部 100ms，以便观察迟到回复；它不是不同的业务 deadline。最终必须收齐所有接受请求，核对每 actor 的实际回复 FIFO、连续计数和提交值，再停止 actor。阶段 deadline 仍为总 3 秒，超时或失败退出不是成功实验；外部子进程仍为 CPU 5 秒/墙钟 10 秒/禁 core。拒绝与超时都保留逐条原始样本，不能删样后通过。

## 验证与后续

独立 Python 从逐条原始样本重算路由、计划、准入分类、deadline、每 actor 回复序列、最终值与计数守恒；不要求两个运行时具有相同拒绝位置或延迟。纯时钟测试另核对精确 100ms 边界、迟到终态不复活、计划不因迟发重基准。BEAM 仅显式 `--compare-beam` 执行，缺少 OTP 29 不回退。

备选方案是直接跑 90 秒实验，或继续增加闭环用例；前者缺少生成器记账回归，后者不能消除 coordinated omission，因此先做此有界切片。后续仍须实现独立长时受限 runner、预热/采样/重复、饱和扫描、fairness、并发失败及超时竞争、原生双平台与同负载吞吐/整机内存门禁。此 ADR 不降低这些要求，不能据短时探测宣称 MVP 完成。
