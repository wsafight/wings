# ADR-0069：独立受限的长时开环采样

- 日期：2026-11-14
- 状态：已采纳（长时测量入口；完整性能门禁仍未通过）
- 扩展：[ADR-0068](0068-bounded-open-loop-counter.md)
- 协议：[BEAM 工作负载](../beam-workloads.md)

## 背景与决定

v5 的 10000 条内存样本和 3 秒阶段只适合正确性探测，不能直接放宽原限制后声称完成性能实验。另增 `--measure` 入口，复用业务、前 100 活动目标、有限 pending、mailbox 和精确计划；原 smoke 参数、3 秒阶段及子进程 CPU 5 秒/墙钟 10 秒不变。

每次长测固定预热 30 秒、采样 60 秒，同一个 t0 连续生成 `90*rate` 条到达，不在边界暂停、清 pending 或重置业务 state。允许四组非 fairness 负载、该组基准速率乘 `2^0..2^7`，不接受任意缩短时段。pending 仍最多 256，外部 deadline 仍从计划时刻算 100ms，超时保留到真实回复；内部租约延续至总阶段 deadline。

每条到达和每条已接受请求的真实回复以固定 40 B big-endian 事件顺序写到独占新建的文件，用户指定的已有文件不能覆盖。记录五个字：`sequence:u64, sent_ns:u64, observed_ns:u64, value:i64, kind:u64`。kind 为 0=已接受到达、1=按时回复、2=超时后的实际回复、3=mailbox_full、4=pending_full；非回复的 observed/value 必须为零。目标和计划由 sequence、case、rate 精确重算，不另存重复元数据。先记录接受到达再记录实际回复，拒绝没有后续回复；所有 warmup/采样事件均保留，文件缺失、截断、重复、乱序到达或未闭合 pending 都使该次实验无效。写入/采样成本属于被测进程，不扣除。

Wings 使用固定 64 KiB 写缓冲和每轮最多 32 票据的轮转探测；BEAM 也固定 64 KiB 缓冲、每轮最多收 32 条结果，保留原生 mailbox 和正常优化，不加串行转发代理。两端开始/采样/结束输出 JSON 控制事件，最终仍验证 state 与清理。独立 Python 在进程结束后逐条读取原始文件，以最多 256 pending 核对准入、每目标实际值、终态和计数守恒，不把采样器自己的大型数组算成运行时内存优势。

## 资源与报告

长测每个独立 OS 子进程 CPU 240 秒、墙钟 130 秒、总业务阶段 120 秒、禁 core、单文件 10 GiB 上限。最高点为 1280000/s，最多 115200000 到达、230400000 个事件，原始文件最多 9216000000 B。无自动重试失败点；保留 stdout/stderr、原始文件、命令、构建/源码标识、环境与失败原因。runner 按最坏原始文件体积检查磁盘余量，不能等磁盘耗尽。资源监测另做有界读，不进行 OOM 注入。

每点固定独立重复 5 次，交替两运行时顺序，运行时串行不互相争用。先完成基准点；`--scan` 才逐点翻倍至最多 8 点，任一运行时出现拒绝、超时或 p99/p999 超标即不再提高，当前点仍跑完五次。缺少饱和点明确标为扫描不充分，不拿最高测得速率当最大持续吞吐。

实验开始前复制 runner、Erlang/gate、artifact 与当前 tracked 源码及本切片新文件到输出目录，记录全部 SHA-256，之后只执行冻结副本。开发构建不能在两次运行间悄悄换掉被测输入；未冻结的探索尝试标为无效，不自动续成正式重复。

报告按计划时刻划分 warmup/采样，延迟从计划到驱动观察真实回复，迟发不重基准。拒绝/超时单独保留在全部到达分母；nearest-rank p50/p99/p999 对有真实回复的样本计算，含迟到，少于 10000 不报 p999。无回复不是零延迟；本入口要求最后收齐，否则实验无效。固定负载候选要求无拒绝/超时、p99≤20ms、p999≤50ms。分位通过不等于吞吐/内存双目标通过。

离线分位不加载所有延迟：逐条核对后用三轮 16-bit radix 计数选择精确 nearest-rank，最多六组固定 65536 桶，延迟范围由 120 秒阶段限定。生成器迟发亦单独计算；拒绝没有回复延迟，但进入迟发统计和拒绝分母。该额外离线扫描不计入业务阶段吞吐，也不在下一个测量子进程运行期间持有随请求增长的样本数组。

采样器每秒记录被测进程树及 Python 驱动的 RSS，总和保留共享页重复计数语义；Linux PSS、macOS physical footprint/压缩/swap 和 CPU 硬配额尚须补齐。没有这些证据时只能报告长时试验和 RSS 观测，不能宣布整机内存门禁通过、最大持续吞吐领先或可试用 MVP。原生 Linux、fairness、并发故障与完整资源账本继续独立验收。

## 备选与重审

不采用完整样本常驻内存：它随速率增长并污染整机内存对照；不只输出直方图：它丢失拒绝、迟到和关联验证证据。选择固定缓冲原始事件，代价是磁盘写入影响测量，因此明确计入而不隐去。后续若更换事件编码、收集器或测量资源口径，须版本化协议并重跑两端相同配置，不能拼接不同 runner 的最优值。
