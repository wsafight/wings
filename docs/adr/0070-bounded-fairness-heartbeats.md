# ADR-0070：同 worker 百万次加法与突发心跳的公平性前置

- 日期：2026-11-14
- 状态：已采纳（短时公平性业务验证，完整公平性门禁未通过）
- 扩展：[ADR-0068](0068-bounded-open-loop-counter.md)、[ADR-0069](0069-streamed-open-loop-measurement.md)
- 协议：[BEAM 工作负载](../beam-workloads.md)

## 背景与决定

既有短时/长时 Counter 没有持续 CPU actor，不能证明心跳不会被热任务饿死。先增加独立 v7 短时验证：101 个真实 actor、每个保留完整 256 B Bytes/binary state、mailbox 1；一个 Wings worker、一个 BEAM 在线 scheduler。它们是调度数量，不冒充 OS 单核硬配额。

actor 1 每个 CPU 请求从零开始做恰好 1000000 次 checked `+1`，成功回复 1000000；完成一次后 state counter 加一，保留 ID 和 padding。已有语言只有唯一 state 携带的 while，不能用局部可变计数；也不能为了跑公平性，把每次加法变成一次 Bytes 分配。因此以六层声明顺序非递归函数，逐级十次调用展开百万次加法，沿用受管帧/根/入口与预算检查，不改语法、ABI 或抢占契约。BEAM 使用同样六层调用，逐步检查 i64，不使用 sleep、阻塞 native 或一次宽整数加百万代替业务。

其余 actor 2..101 每 10ms 各发一个 checked +1 心跳。同一 burst 的计划时刻相同：`t0 + floor(k/100)*10000000ns`，目标 `2+k%100`，不能变成均匀摊开的低峰流量。固定短时段 10/30ms，分别 100/300 条计划心跳；一个真实宿主直接发送，不等待旧回复，BEAM 经原 CAS gate，无代理。保持 256 总实际 pending，其中一个位置预留热任务，最多 255 心跳；满/队列满逐条拒绝，不等待、不跳样、不重试。CPU 每次正常返回后立即续下一次，直到最后计划 burst 发送完；之后不再续热任务，收齐已有热/冷实际结果。

## 观察和失败路径

热任务与冷请求均从实际 t0 观察。心跳外部 deadline 固定为计划后 100ms，迟发不重基准、超时不取消远端提交、pending 保留到真实结果；热请求不混入心跳延迟分位。输出全部心跳逐条样本、全部热任务开始/结束/返回值、每 actor 最终提交计数，独立模型检查所有成功心跳的每目标 FIFO/值、拒绝不执行和最终值。BEAM 在规范化前核对实际到达次序；Wings 的独立票据可跨 actor 不同序观察，不能伪称网络回复到达全序。

同时记录每个冷 actor 的观测最大端到端等待、超时/拒绝，nearest-rank p50/p99、最大值，样本不足 10000 不报 p999。每次热任务记录受管完成数，核对值恰好百万；收齐并检查所有真实 state 后停止。至少一个真实 CPU 任务完成，是否有心跳在热任务未完成时完成另列事实，不把 OS 偶然交错硬编码为必然；单 worker 业务推进只作功能证据。

原业务子进程 CPU 5 秒/墙钟 10 秒/禁 core、总阶段 3 秒、完整 AOT CPU 20 秒/墙钟 30 秒不变，不缩小百万次任务或放宽仿真边界。任何任务未收齐、业务失败或资源未清理使测试失败，不变成成功超时样本。Wings 仍有强制 safepoint/总预算/原子取消，BEAM 保留正常 reduction 调度与优化。

## 后续与重审

此处不接 90 秒长测或公平性饱和扫描，避免混用非 fairness 的任意翻倍率；不改变原每 actor 10ms 到达。之后须在 CPU 硬配额下补长时采样/每 actor 分组、请求让出到实际让出的独立时间戳与候选 p99<5ms、过载组和非过载组、原生双平台以及吞吐/整机内存双目标。心跳端到端延迟不能替代让出延迟，固定调度器数量不能替代 CPU 配额；MVP 仍未完成。
