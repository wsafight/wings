# ADR-0076：计费的 Bytes 复制消息

Bytes 回复限制由 [ADR-0098](0098-accounted-byte-replies.md) 替代；原消息契约保持。

后续 [ADR-0094](0094-typed-host-message-values.md) 为直接宿主开放类型化字节切片复制，保留原合计上限、计费导入与原始整数限制。

- 日期：2026-11-14
- 状态：已采纳（有界业务消息切片，MVP 尚未完成）
- 扩展：[ADR-0051](0051-bounded-int-list-messages.md)、[ADR-0057](0057-accounted-immutable-bytes.md)
- 部分替代：[ADR-0080](0080-central-execution-admission.md) 将相同 4352 字节控制准入移入执行核心，补直接调用/初始化并移除 worker 外层重复票据；Bytes 消息契约不变。

## 决定

现有不可变 Bytes 可用于 state、局部和 fn，但不能跨消息，业务值的使用链尚不完整。为现有 `send_self`、`send` 和异步 `request` 开放 Bytes 参数；沿用原语法和大小写，不采纳待审语法稿。回复仍为原标量边界，宿主原始整数接口不能伪造 Bytes 引用。

每条消息至多 64 个参数，所有 Bytes 参数的复制字节合计最多 65536；每个参数保留独立的规范 offset/length，零长度合法。同条消息可混用标量、RecordInt、IntList 和 Bytes，三个引用 mask 互斥且必须与 schema 精确匹配。新增独立 bytes_mask，源码受管 ABI 升至 v15；旧产物按原版本检查拒绝，历史验证不改写。

发送阶段先验证所有源引用/长度，向发送方 process→tenant→VM 预留精确容量，再 fallible 分配独立 staging Vec；不在每个空 envelope 内嵌 64 KiB 数组。每至多 256 字节复制经过强制预算/取消/原子让出检查，检查点之间不持有源堆 Rust 借用。源引用由 compiler 根保持，staging 由自己的票据计费，取消/失败归还。原有记录/列表复制限制保持。

新增载荷控制字段使保守 invocation 控制区估算超过原 4096 字节，单 worker 和 Scheduler 统一在执行前预留 4352 字节，并以实际控制类型大小校验；不提高资源上限或少计字段。准备执行失败时仍保留 mailbox 原载荷，直到准备全部成功才将其移入活栈。

持目标唯一 mailbox 发布权时校验完整 Pid、schema 和容量，将 staging 票据转至接收方 account，再完成 envelope 准入和发布；共同祖先不重复扣费，失败保留既有账目并清理未发布载荷。已经接受的消息不因发送方失败或请求超时而撤回，队列中的字节继续由接收方计费，不共享源堆引用。

接收方取得唯一执行权后，在自己的精确非移动堆重新构造 Bytes；目标数据分配前另行预留，复制与空槽搜索有界分块。所有已导入参数保存在入口根，后续参数触发 GC 不丢失前面参数；handler 退出统一清入口根。staging 在导入完成或失败后释放，导入期间源副本和目标副本都计费。导入失败走原受管失败/旧状态不提交/监督路径；stop、超时保留、取消与清理沿原生命周期，不以票据取消冒充消息撤回。

## 验证

独立载荷检查覆盖规范分段、mask、空/满/越界、三级准入、同 VM 转移净增量、失败回滚和最终零；真实 AOT 覆盖自发送、目标发送/异步请求、一/双 worker、混合参数、多参数导入 GC、源后续更新/GC/失败后的副本独立性、边界及取消清理。原完整 AOT、workspace check/tests/clippy/fmt/MSRV 和两个首要平台按既有条件验证，不扩大业务或 AOT 时限。

Bytes 仍是字节串，不添加 UTF-8/字符串语义、引用回复、任意记录 schema 或共享 blob。本片推进业务消息与账本，不能据此认定完整业务值、资源隔离、长时公平性、原生双平台或 BEAM 吞吐/整机内存门禁通过。
