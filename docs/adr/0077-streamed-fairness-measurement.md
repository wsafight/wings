# ADR-0077：连续 CPU 与突发心跳的独立长时采样

- 日期：2026-11-14
- 状态：已采纳（长测入口；公平性与 MVP 门禁未通过）
- 扩展：[ADR-0070](0070-bounded-fairness-heartbeats.md)、[ADR-0072](0072-scheduler-yield-observation.md)
- 复用：[ADR-0069](0069-streamed-open-loop-measurement.md)、[ADR-0075](0075-platform-memory-observation.md)

## 决定

保留 v7 的 10/30ms、原 CPU 5 秒/墙钟 10 秒/阶段 3 秒及完整 AOT 20/30 秒边界，另增 v8 长时入口。业务仍是 101 个 actor、完整 256 B 状态、mailbox 1、单 worker/在线 scheduler；热 actor 每次从零执行恰好百万次 checked 加法，其余 100 个 actor 每 10ms 同时各到达一次心跳。心跳计划不因热任务或旧回复暂停，不改为匀速摊开发送。总 pending 仍是一个热任务加最多 255 个心跳；拒绝/超时不删样、不重试，超时保留实际请求到真实结果。

连续 30 秒预热加 60 秒采样，共 900000 个计划心跳；热任务至少续发至业务 t0 后 90 秒，再收齐已接受的热/冷结果并检查全部状态。若生成器已迟到，仍先发完原计划再停止热任务，拒绝/超时保留；不能在最后一个计划 burst 的 89.99 秒提前停止整个采样窗。业务阶段 120 秒，隔离子进程 CPU 240 秒/墙钟 130 秒/禁 core，沿用独立长测的文件和 observed RSS 停止边界；这些是保护性边界，不是 OS 单核硬配额。长测不会自动进入完整 AOT 或 CI。

热/冷请求的接受、拒绝和实际完成按发生顺序写入独占新建的固定 40 B 大端事件记录，使用有界 buffer；运行端不保留 900000 条内存历史。心跳序号决定目标和计划时间，记录实际发送/观察和值。热任务另用事件类型和独立序号，必须恰好回复百万，保留每个任务的开始/结束；超过固定热任务历史上限、丢失结果、写入失败、状态或清理失败均使实验无效。不能用完成数替代实际业务执行。

Wings 可显式启用原 64 条计费让出 FIFO，每轮最多取 32 条并流式落盘，完整保留初始化期样本。让出时间仍相对独立观测起点，最终记录它与业务 t0 的偏移；冷请求端到端延迟和请求让出到真实切回的延迟分别统计。后继请求可能先于上一轮返回确认到达，故请求时间与返回时间各自单调、每对请求不晚于返回，不要求两对区间互不重叠；原 token 的后继请求保留契约不变。FIFO 满的 dropped、序号缺口、无数据及计数溢出显式披露，不以零样本证明 p99<5ms；启用观测的实验须记录额外开销模式，不能冒充默认性能。

## 独立核对与实验范围

验证器按流重放全部事件，检查 900000 次计划、每目标 FIFO/提交值、实际 pending 上限和拒绝、热任务单在途/完整返回、最终零 pending、三种时间基准及最终状态；伪造、截断或缺样不能通过。30 秒前的计划归预热，后 60 秒归采样，迟到完成不跨阶段重分类。分全局及每个冷 actor 报到达、拒绝、超时、最大等待和 nearest-rank 分位；样本少于 10000 不报 p999。热任务的请求耗时与采样窗内实际完成率、生成迟到及让出延迟另列；请求耗时包含排队和宿主观察，不冒充独占 CPU 时间，不用聚合心跳直方图掩盖个别 actor 饥饿。

固定输入五对重复，交替 Wings/BEAM 顺序，冻结执行文件、AOT 产物、BEAM 源码、验证器与输入哈希；复用原平台内存采样和采样器成本记录。每轮的失败都保留，禁止选最好一轮。先只验证固定 10ms burst，不自行发明公平性饱和倍率或降低心跳频率；过载/非过载分组、CPU 硬配额、原生双平台、完整监测开销与同负载吞吐/整机内存双目标仍须另行完成，不能据长测正常退出宣布 MVP。

## 替代方案与重审

循环启动短测会反复清空队列和状态，无法证明连续热任务下的长时公平性；把全部样本放进运行端数组会改变被测内存；提高短测时限会混淆功能和实验边界，均不采用。以后改变 burst、CPU 工作量、窗口、deadline、观测模式或阶段归属时，重新冻结协议并保留旧数据，不反写历史结果。
