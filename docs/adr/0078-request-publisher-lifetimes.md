# ADR-0078：请求票据保持到结果端与消息端都结束

- 日期：2026-11-14
- 状态：已采纳（请求资源生命周期修正）
- 部分替代：[ADR-0021](0021-bounded-requests.md) 的超时/取消取走后立即复用槽位、[ADR-0040](0040-language-request-events.md) 与 [ADR-0054](0054-bounded-multi-worker-scheduler.md) 的完成事件入队/发起方退出后立即归还请求票据。
- 沿用：[ADR-0047](0047-cross-thread-ingress-requests.md) 的结果端/发布端双端租约，不混用三类请求身份。

## 问题与决定

宿主标量请求取走超时/取消结果、语言完成事件入队或发起方退出时，对端已接受消息仍可排队或持有活栈。此前单 worker 与 Scheduler 语言表立即释放请求槽和 requests 票据；反复超时可绕过请求容量，直到另一个消息额度先饱和。完整 RequestId 代次避免了串回包，却没有保留仍存活请求的准入成本。

- 每个内部请求分别记录结果端是否结束、消息发布端是否结束。只有两者都结束才释放 requests 票据并递增槽代次；耗尽代次退休。请求表仍预分配固定容量，不为每次请求新建 Arc、通道或动态表，不改 ABI、语言拼写或现有容量上限。
- 宿主 `take_reply` 可以立即取走已选定超时/取消结果；该 ID 随即不可重复消费或取消。只要原消息仍排队/执行，槽和原账户票据仍保留；新请求按原表容量和三级额度拒绝。消息正常返回、失败、stop 清理后才结束发布端。先完成消息而结果尚未取走时，同样保留槽和票据。
- 语言完成事件仍可在超时/取消后尽早进入发起方 mailbox。预留的消息/字节票据移入事件，结果端随入队结束，但 requests 票据等到目标消息完成/清理；事件入队后原能力不可取消。mailbox 满时仍保留完整事件路由与预留，不能丢事件或另分配容量。
- 发起方退出丢弃尚未投递的完成事件并归还其消息/字节预留，结果端结束；目标消息不撤回，requests 票据和原账户租约保持到目标消息结束。槽复用/监督重启不会收到旧事件。目标退出结束所有指向该代次的发布端，选择 Failed 或已到期的 TimedOut，保留既有终态。双方为同一进程时一次清理两端。
- 完成路由移出后不再保留 HandlerId 或事件预留，存活项仅保留固定请求身份、目标/发起方代次、终态、deadline 和原 requests 票据。worker/Scheduler 关闭后正常取消并清理全部活栈、队列和请求表。取消只选择终态，不能冒充消息发布完成；迟到回复既不覆盖终态，也不命中新代次请求。

## 验证与边界

先用固定单槽与零 timeout 重现“结果已取走但目标仍排队，requests 已归零”的旧行为，再验证消息完成前反复请求均拒绝且资源零变化，完成后复用代次、旧 ID 拒绝和最终归零。真实 AOT 覆盖排队/活栈超时与取消、状态继续提交、目标失败/stop、发起方退出/槽复用、自请求、完成 mailbox 满与一/双 worker。固定表模型覆盖结果/发布两种结束顺序、代次耗尽、事件已入队后的取消拒绝、两端退出与旧回复；不靠调大容量或 deadline 通过测试。

运行 workspace check、debug/release 测试、all-target clippy、fmt、MSRV、受限 debug/release AOT 与可用 Linux 功能回归。保留原 CPU/墙钟/阶段上限；原生 Linux、完整业务值、全部资源账本、长时公平性和同负载 BEAM 吞吐/整机内存门禁仍独立待验收，不据此宣布 MVP 完成。
