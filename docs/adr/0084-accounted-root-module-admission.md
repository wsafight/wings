# ADR-0084：计费根拒绝未计费工具模块

- 日期：2026-11-14
- 状态：已采纳（模块加载与执行资源边界修正）
- 部分替代：[ADR-0044](0044-native-module-leases.md) 允许未计费工具模块接入任意资源树的组合，以及 [ADR-0079](0079-accounted-vm-bootstrap.md) 尚未收敛的计费根模块入口。
- 沿用：[ADR-0083](0083-accounted-module-execution.md) 对计费模块执行池的要求、显式配置和失败回滚。

## 决定与理由

计费模块已经不能换用工具池，但计费根仍能接收 `load_trusted` 的未计费模块，从反向组合绕过模块加载预算。根选择计费模式后，应在接入代码时验证模块租约，而不是等调用者自行遵守加载约定。

- `vm_accounted` 的整棵后代树只接收由本 VM `load_accounted` 创建的模块。未计费模块通过显式池初始化、带堆初始化、受控调用、owned task、worker/Scheduler spawn 或镜像接回时，在进入 initializer/handler、创建进程和业务堆、占用调度槽或消费镜像前拒绝。
- 校验从资源账户推导根已有的启动计费标志，不添加隐藏账户、自动补模块租约或重复收费。带租约模块仍先校验原 VM 身份；跨 VM 保留既有错误分类。
- `load_trusted` 仍可独立加载、在工具池或旧 `vm` 工具树运行；它不是可以直接接入计费根的廉价加载方式。工具实例和镜像被计费树拒绝后，仍能回到原工具池运行。旧 `vm` 的零启动基线及其显式计费子节点模型不在本次替换范围内。
- 拒绝保持账目、池、旧提交状态、任务活动标志与镜像可用性。worker/Scheduler 拒绝后仍可在原容量内接入合法计费模块，不消耗 generation 或业务执行机会。

不修改 ABI v15、语言类型拼写、GC、资源上限、控制预留或 CPU/墙钟时限。这项检查不追溯已经在工具入口发生的加载成本，也不把所有宿主适配器分配或动态装载器内部开销写成已闭环。

## 验证

用可信 Rust ABI fixture 先复现计费根接受未计费模块，再检查拒绝前入口调用数为零、带堆初始化无分配、受控/owned task 与镜像拒绝零变化，随后工具路径成功执行。真实 AOT 对标量和 Bytes 模块验证相同初始化与单/双 worker 调度准入，拒绝后用原单槽容量运行本 VM 的计费模块，清理回到根启动基线。
