# ADR-0085：模块路径解析先准入控制预算

- 日期：2026-11-14
- 状态：已采纳（模块加载资源顺序修正）
- 后续：[ADR-0128](0128-native-module-image-admission.md) 在文件预算内读取快照，释放后补足映像跨度，成功才动态装载；本决定的控制先准入顺序保持。
- 部分替代：[ADR-0044](0044-native-module-leases.md) 在路径解析和库元数据读取之后一次预留模块预算的顺序。
- 沿用：[ADR-0083](0083-accounted-module-execution.md)、[ADR-0084](0084-accounted-root-module-admission.md) 的模块与执行树身份要求。

## 决定与理由

`load_accounted` 已在清单解析和动态装载前预留模块预算，但 `canonicalize` 和库路径拼接在此之前创建临时路径。将已有控制容量的准入提前，使资源不足时不先进行路径分配和文件查询。

- 确认传入账户是 VM 后，先预留原 2 MiB 模块控制预算，再执行路径解析、拼接和库文件元数据查询。控制预算不足时优先返回 VM 资源错误，即使目录无效；不尝试文件查询或动态装载。
- 库仍须为不超过原 64 MiB 的普通文件，随后追加按原 4096 B 向上取整的库页预算。两个固定票据由同一个模块租约持有，总额仍为原库页加 2 MiB；不添加账户、重复计费或扩大任何限额。
- 控制票据在路径临时存储之前创建，在失败路径的临时存储释放后归还。路径、元数据、库页追加、清单、符号或分配失败都回到调用前账目，不留半模块。正常 clone、handler、实例和活栈仍共享同一租约，最后代码所有者释放动态库后再归还两部分预算。
- `load_trusted` 的独立工具加载不预留 VM 预算；账户层级错误保持原诊断。文件不可变的可信装载要求、库/清单上限、ABI v15、CPU/墙钟和执行容量均不变。

控制预算仍是有界元数据与临时缓冲的保守逻辑额度，不是 allocator、系统调用内部存储、动态装载器或平台映射的精确计量，也不提供硬内存隔离。

## 验证

先在旧实现复现不足控制额度时优先报目录错误，再验证零、少一字节、精确控制容量与路径失败回滚，分别覆盖旧工具根和带启动计费的根。真实 AOT 保留精确完整模块预算、少一字节、重复加载、最后持有者、暂停取消和坏产物回滚；新增控制不足早拒绝、精确控制但不足库页时拒绝及账目零变化。
