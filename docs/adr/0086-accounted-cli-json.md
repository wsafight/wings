# ADR-0086：CLI 请求缓冲与有界 JSON 解析准入

- 日期：2026-11-14
- 状态：已采纳（CLI 请求适配层资源切片）
- 部分替代：[ADR-0081](0081-accounted-default-cli.md) 尚未计费的逐行缓冲及通用 JSON Value 树路径。
- 沿用：原 16 MiB 三级逻辑字节额度、64 KiB 输入行上限、64 个 handler 参数及正常返回后输出的顺序。
- 后续：[ADR-0088](0088-owned-cli-stdio.md) 收敛业务 stdin/stdout 的独立预留、描述符和缓冲清理，原请求适配器预算与协议保留。

## 决定与理由

原 CLI 每行创建 Vec，再将整个 JSON 解析为 Value 树。嵌套对象和任意长数组会先分配，再因协议或参数类型失败；这些分配没有经过 process/tenant/VM 准入。通用 Value 也会覆盖重复字段，使一个请求的消息名或参数取决于字段顺序。

- 在创建请求缓冲和取消标志前，向 CLI 的 process 账户一次预留 264 KiB：64 KiB 复用行缓冲、192 KiB 转义解析增长余量、8 KiB 固定结构与控制余量。标量和堆模式均从原 16 MiB 额度中支付；不提高限额或从其他账户补足。准入失败不读输入、不进入 initializer；释放所有适配器存储后归还预留。
- 使用工作区已有 serde/serde_json 的 streaming visitor，不再构建通用 Value 树。只接受恰好一次的 `message` 和 `args`，顺序不限；消息名遵守产物已有的非空、至多 256 UTF-8 字节且无控制字符规则，参数为至多 64 个 JSON 整数、布尔或 null。JSON 转义和数值词法仍交由 serde_json 校验，不自研 JSON 词法解析器。
- 重复、缺失或未知字段、超长消息名、额外参数、字符串/嵌套参数和尾随 JSON 均在 handler 执行前拒绝。重复字段改为明确错误，不继续保留旧 Value 覆盖行为。整数、Bool、Unit 按 handler 签名检查；浮点/指数形式和 i64 越界值不能转换为 Int，引用/Pid/RequestId 仍不是 JSON 参数。
- 行上限继续包括换行符；支持 CRLF 和末行无换行。读取前清空并复用同一个已准入缓冲，超长行不先复制超额部分。成功、解析错误、类型错误、资源失败和 I/O 失败均保留原已提交状态/已输出行的语义，不执行当前非法请求，不承诺输出失败时回滚已完成 handler。
- 回复直接序列化固定结构，保留 `{"reply":...}` 和 `{"accepted":true}` 的外部格式，不为输出再建立 Value/Map。取消标志、行缓冲和请求解析的逻辑预算跟随同一适配器；复用已锁定的 serde 包，不添加第三方包或改变其版本。
- 字符串出现在对象、数组或标量参数位置时返回固定错误，不在错误文本中格式化整段用户字符串；避免 JSON 允许的 DEL 等字符在 Rust Debug 转义中膨胀，错误路径也须遵守同一预留。

这是请求适配器的保守逻辑容量，不是 allocator、标准 I/O 全局对象、OS 文件缓冲或主线程栈的精确计量；CLI 启动参数和完整宿主账本仍待收敛，不据此宣布所有分配闭环。ABI v15、语言拼写、业务预算、池/堆容量、CPU/墙钟与阶段截止时间不变。

## 验证

先记录旧真实 AOT CLI 折叠重复 message/args 并执行 handler 的行为。新增三级资源不足/精确边界、拒绝账目零变化、重复请求复用、释放回到根基线，以及最大行、转义/Unicode、64/65 参数、i64 边界、浮点/指数/越界、未知/缺失/重复字段、嵌套值和尾随内容回归。真实 CLI 检查非法请求不产生当前回复，已有合法回复保留；正常 Int/Bool/Unit/单向消息和堆模式继续通过。
