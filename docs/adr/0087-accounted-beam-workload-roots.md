# ADR-0087：BEAM 对照驱动使用计费根并报告清理基线

- 日期：2026-11-14
- 状态：已采纳（业务对照资源集成切片）
- 部分替代：[ADR-0079](0079-accounted-vm-bootstrap.md) 尚未收敛的对照驱动根构造，以及 v1–v8 Wings 驱动以零启动根清理归零的判断。
- 沿用：原业务协议、actor/state/消息规模、FIFO、失败恢复、并发窗口、资源限额、CPU/墙钟与阶段截止时间。

## 决定与理由

六个 BEAM 对照驱动已经使用计费模块、tenant 和 process，却仍由零启动成本的 `vm` 创建。用于未来性能/内存对照的实际业务应经过同一计费根边界，不再将工具模型视为完整 VM 路径。

- 单 actor、多 actor、双发送者、有限准入、开环和 CPU/心跳公平性驱动均改用 `vm_accounted`。根创建失败即沿原驱动错误路径退出，不隐式回退到工具根。原各驱动 32/128/256 MiB 等额度不提高；根/门闩成本占用原剩余额度。
- 模块和子资源创建前保存实际根启动 `Resources`，停止/失败清理并释放所有派生持有者后要求 used 精确等于启动值，包含其余维度为零。成功/预期业务失败报告中的 `resources_released: true` 表示派生业务预留已归还，同时给出正的 `bootstrap_bytes` 与相等的 `remaining_bytes`。不报告根无成本，不硬编码跨平台尺寸。
- 当前 v1–v7 正确性入口严格校验清理回执；新增 v6/v8 长测采集同样要求回执，缺失、bool/float/负数/超 u64、零启动或剩余不等均为实验无效，不把问题记成性能差异。
- 历史冻结结果和原始 trace/hash 不回写。离线重放入口仍允许历史报告没有这两个字段；如果任一字段出现则必须完整验证，不容许半份/伪造回执。新采集在调用重放前强制要求回执，由启动调用方明确传入预期运行时，不能用变更报告 runtime 绕过 Wings 检查。

这只是启动计费与清理判定的集成，不包含驱动全部 JSON/Vec/trace/标准 I/O 分配，也不把根逻辑成本解释为 RSS 或整机内存。旧冻结结果不成为新版本性能证据；新代码的正确性通过后仍须分别完成原生双平台、CPU 配额、代表性长时负载和 BEAM 吞吐/整机内存双门禁。

## 验证

先保存旧真实 v1 驱动输出 `resources_released: true` 但没有启动回执的缺口。用独立回执检查器验证成功/缺失/伪造类型/不等/超范围与历史离线兼容，完整 AOT 和显式 BEAM v1–v7 继续核对相同业务。新采集即使运行时字段被修改也须拒绝；独立模型验证历史重放和新采集要求不会混同。

运行 workspace check、all-target clippy、fmt、Rust 1.85.0 all-target check、debug/release all-targets/doc-tests、完整受限 AOT、依赖/unwind、文档和可用 Linux 功能回归。不扩大原容量或时限，不修改冻结测量，不宣布性能门禁通过。
