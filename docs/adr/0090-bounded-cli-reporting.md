# ADR-0090：CLI 帮助与诊断的计费输出和失败处理

- 日期：2026-11-14
- 状态：已采纳（CLI 控制输出切片）
- 部分替代：[ADR-0088](0088-owned-cli-stdio.md) 与 [ADR-0089](0089-bounded-cli-startup-arguments.md) 保留的帮助/stderr 全局输出路径。
- 沿用：原帮助内容、正常错误前缀与退出码、16 MiB 限额、业务 I/O、ABI v15 和执行预算。

## 决定与理由

原帮助使用 println，stdout 已关闭时 panic；诊断使用 eprintln，输出失败同样可能 panic，并初始化存活至进程结束的全局 I/O 对象。错误内容还可能来自产物解析：64 KiB 范围内的非法 JSON 字符串能在来源错误格式化时膨胀，完整转发 stderr 没有输出上限。

- 计费 VM 根建立后、tenant/process 和参数解析前，先从原 VM 字节额度预留 8 KiB。4 KiB 为固定诊断缓冲，其余为 stderr 描述符副本和控制余量；这是 VM 启动/控制输出，不冒充业务进程分配，不提高原 16 MiB 限额。保留至诊断输出结束，先销毁描述符再归还预留。
- 复用已有 close-on-exec 描述符复制路径，stderr 由独立 File 持有；帮助按需复制 stdout，以标准库 write_all 直接写静态内容。两种输出均不建立 BufWriter 或标准库全局锁，不为格式化再创建 String。帮助写失败转换为正常错误与退出码 1，不 panic；诊断写失败不递归打印第二个错误，也不改变此前业务失败/参数失败的退出码。
- 单条诊断含换行最多 4096 B。固定缓冲接收格式化片段，超限时在 UTF-8 字符边界截断，末尾追加 `... [truncated]`；来源错误和用法不逐字重试，不因截断而 panic。已有成功业务回复不撤回，当前失败不产生成功回复。
- 根或控制输出初始化失败时，使用固定静态启动失败文本直接写继承的 stderr，允许中断重试且不另建账户或分配缓冲。此路径不能预留尚未建立/已拒绝的根，属于明确的可信启动应急边界，不是未计费业务输出的回退。

本切片只计费控制输出自有的缓冲与描述符，并限制对外诊断字节；来源组件返回的错误 String、Rust 启动/主线程栈、allocator、动态装载器和内核队列仍不是完整账本。产物错误在来源内部的构造膨胀尚须收敛，截断输出不能充当其分配已受控的证据。原生双平台、完整资源隔离和 BEAM 吞吐/整机内存门槛保持。

## 验证

保留帮助 stdout 断管触发 panic 的真实复现，以及有界非法产物放大 stderr 的旧字节数。验证 VM 级零/少一字节/精确预算、错误层级和准入前不打开文件、打开失败回滚、缓冲固定上界、UTF-8/精确边界截断、写失败正常返回、描述符清理与原所有者保留。真实 CLI 在帮助/参数错误/运行失败的 stdout/stderr 断管下均不 panic；非法产物诊断含固定截断尾部，正常请求和已有成功回复保持。
