# ADR-0091：产物清单字符串在类型错误构造前校验

- 日期：2026-11-14
- 状态：已采纳（产物错误来源边界修正）
- 部分替代：[ADR-0090](0090-bounded-cli-reporting.md) 尚未收敛的清单 JSON 错误放大路径。
- 沿用：产物格式/ABI v15、64 KiB 清单上限、2 MiB 模块控制预留、现有 serde 解码和语义校验。

## 决定与理由

CLI 截断诊断只限制输出。清单中的长字符串可先被 serde 的类型/未知字段错误展开，再作为 String 返回；原控制预留已经销毁，错误本身仍占内存。独立探针用 60,002 B 输入复现 360,072 B 错误文本与 720,098 B 的返回错误存储，VM 账目已回到启动值。累计分配请求和活跃存储须分别记录，不将前者解释为峰值或 RSS。

- `Manifest::read` 在现有类型解码前增加一次不构建对象树的 serde streaming visitor，遍历 JSON 键、值和数组，所有字符串限制为现有名称规则的至多 256 UTF-8 字节、无控制字符。超限/控制字符使用固定错误，不把原字符串加入诊断。
- 现有合法清单中的字符串均为字段名、名称、目标或类型拼写，已经满足该边界；原有效对象、字段顺序、序列表示和单元枚举表示继续由原 serde 实现接受。不重写 JSON 词法、Manifest/Handler 的 Deserialize 或 ValueType，不增删字段，不借此修改语言语法或产物格式。
- 预检仍使用 serde_json 的转义、UTF-8、数值和递归限制；其暂存在进入原类型解码前销毁。读取字节和两次解析均在原模块控制预留范围内，输入仍至多 64 KiB，不扩大资源限额。增加一次有界启动解析，不把此项写成加载性能优化。
- 预检通过后，原重复/未知字段、字段类型、名称/handler/参数数量、目标/ABI、能力与引用边界继续检查。类型错误只可能引用已通过长度/字符检查的短字符串，避免从长键、类型名或错误位置再次构造输入量级的诊断。

此项解决文件加载清单的已复现放大，不声称所有 VM 来源错误和 String 生命周期已闭环。直接对公开类型调用 serde 仍属调用方工具路径；动态装载器、其他宿主错误、allocator/可信启动存储和完整业务账本仍须收敛。CLI 4 KiB 输出上限继续保留，原生双平台 CI 与 BEAM 双门禁不变。

## 验证

保留旧错误长度、返回后存储、累计请求与账目；修复后对同一输入重测。回归覆盖顶层/字段/类型/handler/参数/未知键位置、转义与控制字符、256 UTF-8 字节边界、短非 ASCII 错误、对象/序列/枚举表示兼容、递归/截断/尾随 JSON。真实默认/堆 CLI 拒绝非法产物且不进入原生装载，错误足够短而不依赖末端截断；固定输出截断和断管处理继续独立回归。
