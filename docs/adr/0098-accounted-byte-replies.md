# ADR-0098：计费的 Bytes 回复

- 日期：2026-11-16
- 状态：已采纳（有界字节回复切片；MVP 门禁仍未完成）
- 部分替代：[ADR-0097](0097-accounted-int-list-replies.md) 与 [ADR-0076](0076-accounted-byte-messages.md) 对 Bytes 回复的限制。

## 背景

Bytes 已支持计费状态和消息，但不能回复，使现有业务值的异步往返不完整。不能把业务堆编号返回宿主，也不能让请求槽常驻一份 64 KiB 缓冲。

## 决定

允许 `-> Bytes` 和精确匹配的 `(RequestId, Int, Bytes)` 单向完成入口；单次回复为 0..=65536 字节，不新增字符串、通用记录或语法大小写方案。ABI 继续 v15，旧 runtime 会在清单验证拒绝新增回复及完成签名。

生成入口返回后，在原协程内为回复及候选引用状态建立出口 shadow frame，沿既有 `export_bytes` 先检查引用和长度，再向目标 process/tenant/VM 预留独立存储，每至多 256 字节扣预算并检查取消/让出。复用已复制缓冲，不进行第二次无检查的整块复制；随后预留结果控制对象，全部成功才提交候选。取消、预算、无效引用和资源拒绝正常返回且不提交状态；不跨 ABI unwind。

`BytesReply` 拥有不可变 `Vec<u8>`、存储票据和控制票据；Clone 仅共享已计费的存储，最后拥有者释放才归还。结果不持 actor、模块、业务堆或执行栈。同步宿主用 `invoke_bytes`，显式执行返回 `CompleteBytes`，worker/Scheduler/监督/固定 ingress 返回 `ReplyBytes`；原整数调用执行前拒绝字节入口。JSON 输出 `{"reply":{"bytes":[0,255]}}`，流式序列化，不另建输出数组；JSON 输入仍只接受原标量。

语言完成信封持有结果租约和规范第三参数段编码，mask 为 4；不在 Scheduler 锁内复制最多 64 KiB 或新增结果内容分配。该不可变载荷不暴露给业务进程共享访问，发起方仍通过原分块导入和入口根机制获得自己的计费堆副本。原目标的结果存储保持计费至末信封/宿主结果释放，不净转移共享结果的票据。非成功完成使用空字节值，必须先判 status。

队满保留结果与完成路由；发起方退出/导入失败、目标退出、超时/取消与迟到结果沿原唯一终态和 publisher 生命周期清理。早期超时/取消不撤回目标业务。继续使用 4352 字节执行控制预留与原资源上限。

长测冻结必须包含本次尚未提交但参与构建的源码，并排除未采纳的 `docs/proposals/`；v6 与 v8 使用相同 Git 文件集合，不以 HEAD 哈希代替实际输入哈希。

## 替代方案与影响

- 返回堆编号会破坏堆归属和生命周期，不采用。
- 完成派发时再复制结果会在 Scheduler 锁内引入 64 KiB 工作及失败分支，不采用。
- 每槽固定 64 KiB 提高空闲成本，不采用。
- 结果存储租约可在目标停止后继续计入原 process 路径；这是真实保留，不代表泄漏或 RSS 已释放。

## 验证与重审

检查器/共享 LSP、IR、Manifest、worker/Scheduler 独立验证六种回复的精确类型与交叉错配。验证空/1/256/257/65536 字节、三级存储和控制拒绝、Clone/末拥有者释放、出口预算/暂停/取消/Drop、候选不提交、GC、宿主/ingress/监督及一/二 worker；满队列、发起方退出和导入失败须清理。真实 AOT 的成功/零超时/取消/失败 × 自己/子进程保留合法竞争，不强求跨 worker 取消获胜。沿原 CPU 20s/墙钟 30s/core 0 和三秒业务阶段执行。

扩大值大小、改变所有权、允许直接跨堆共享或变更 ABI 时重新决策。本片不完成字符串/通用业务值、完整资源账本、长时公平/故障、原生双平台或同负载 BEAM 双门禁。实际证据见[验证记录](../validation-2026-11-16.md)。
