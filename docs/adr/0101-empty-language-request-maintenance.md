# ADR-0101：空语言请求表的维护快路径

- 日期：2026-11-16
- 状态：实验后回退（五对无稳定收益，未保留候选实现）
- 原拟部分替代：[ADR-0054](0054-bounded-multi-worker-scheduler.md) 的每轮无条件语言请求维护扫描；当前沿用原实现。
- 沿用：[ADR-0078](0078-request-publisher-lifetimes.md) 的结果端/发布端双端生命周期；不改变 [ADR-0099](0099-unready-result-poll-fast-path.md) 的宿主结果表。

## 背景与假设

Scheduler worker 每轮在共享锁内调用 `maintain`，扫描语言请求表以选择超时并投递完成事件。纯宿主请求不使用这个表，仍会遍历最多 256 个槽两次并读取时间。假设空表快路径可以减少固定调度开销；它不等于已测吞吐收益，也不解释全部尾延迟。

## 候选决定（已回退）

- `State` 在原共享锁内保存语言请求存活槽数，初始化为零。该字段包含在已有 `size_of::<Shared>()` 控制预留内，原资源上限不变；不增加动态分配、线程或原子操作。
- 目标 mailbox 成功接收请求后，统一安装 pending 并增加计数；任一发布前失败不得增加计数。已耗尽 generation 的槽仍不可复用。
- 只有 publisher 已结束且 completion 路由已移出时，统一回收槽并减少计数。超时、取消、完成事件投递或 owner 退出本身不能提前减少；目标/双方退出、旧回复和重复清理沿用原语义。
- `maintain` 在计数为零时直接返回，不读时钟或扫描请求槽。非零时完整保留原扫描、期限选择、mailbox 满路由保留与投递顺序，不新增稀疏索引或更改非空表算法。
- Scheduler 关闭仍先停止/join worker，再清理所有 pending 并将计数归零。所有修改在同一锁内，不引入跨锁快照。

ABI v15、语言语法、业务状态/消息、容量、safepoint、预算、quantum 和原测试时限保持不变。不是新的请求准入或关闭模型。

## 验证、风险与回退

最大风险是计数与真实 pending 不一致：错误的零会漏掉超时/完成事件，提前减少会逃逸 publisher 租约。因此集中安装与回收，覆盖发布前失败、非首槽、双端两种结束顺序、mailbox 满、超时/取消、owner/target/双方退出、迟到/旧 generation、代次耗尽与关闭后保留 handle。既有真实 AOT 的一/双 worker 请求、引用回复和并发恢复继续执行。

先运行受限定向测试，再执行 debug/release workspace 独立 harness、完整受限 AOT、check/clippy/fmt/MSRV 和真实 BEAM 正确性 smoke。随后固定 hot-queue 10000/s、30s 预热/60s 采样、五对交替，保留所有延迟、迟发、拒绝、超时、分口径内存与冻结输入。不同时修改 driver、timer 或资源上限。

无稳定收益或任何生命周期回归时，只撤销计数与空表提前返回；保留原扫描和失败证据。当前无 CPU 硬配额/可靠隔离、最新原生 Linux 及同负载 BEAM 双目标验收，不据本实验宣布 MVP 或领先 BEAM。

## 实验结论

debug/release 各 591 项、完整 AOT 和真实 BEAM 正确性 smoke 通过，但 hot-queue 原 10000/s 五对采样中，候选 86 次超时、1350 次队满，原版 0 次超时、475 次队满；p99 4/5 对较低，p999 仅 2/5 对较低，未建立稳定收益。主机未隔离且发生器迟发存在差异，不能认定计数改动单独导致退化，也不能用局部快路径或最好轮次替代端到端证据。

撤销计数、集中安装/回收改动及候选专用测试，当前完整恢复 `8cc7878` 的代码；冻结的候选源码/二进制、726 个输入哈希和十轮原始数据保留，见[验证记录](../validation-empty-request-optimization-2026-11-16.md)。ADR-0099 保持，不改变 timer、预算或负载。
