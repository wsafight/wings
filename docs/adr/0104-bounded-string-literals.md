# ADR-0104：有界字符串字面量

- 日期：2026-11-17
- 状态：已采纳（字符串构造切片）
- 延续：[ADR-0103](0103-accounted-utf8-string-values.md) 的独立 UTF-8 类型、计费副本与分块执行。

## 背景与决定

String 已可保存和转换，但构造文字仍需逐字节拼装，无法作为最小业务语言试用。本轮增加双引号字面量，支持直接 UTF-8 与 `\"`、`\\`、`\n`、`\r`、`\t`、`\0`，不支持其他转义、插值或多行原始文本。单个解码值最多 65536 字节，沿用 1 MiB 源码限制；IR 独立检查单个和程序内合计最多 1 MiB 的字面量数据，防止手写 IR 绕过源码边界。未知转义、未闭合和解码超限在编译前诊断，错误恢复继续识别后续入口。

后端将 UTF-8 编码放入模块只读数据段，不把文本逐字节展开为 IR 或栈数组。新增可信 HeapCall 的固定三整数 scratch 传静态指针及长度；runtime 在 64 KiB 边界内先预留独立 process/tenant/VM buffer，分块校验 UTF-8/复制，每至多 256 字节检查取消/让出并扣预算。原生常量属于模块租约，受管副本属于进程，代码所有者随 Invocation 保持，暂停时只读指针仍有效。空字面量也创建独立 String 槽，不伪造空引用。

源码 ABI 升至 v17，新增 HEAP_STRING_LITERAL，context/EffectRequest 布局、控制预留和各资源上限不变，旧产物须重编译。静态指针沿可信 native ABI，不构成不可信代码沙箱；地址本身由编译器保证合法，runtime 检查长度和内容。String 消息/回复、内容比较和通用记录仍独立推进，不通过字面量绕开传输边界或大小写评审。

## 替代方案与影响

逐字节 replace 会复制多次、放大代码与根数量，不采纳。把只读数据直接当受管 String 会绕过每进程计费与生命周期，不采纳。字面量驻留/共享可作为后续优化，但须另行证明所有权与计费，不在本轮引入。

## 验证与重审

覆盖所有转义、中文/emoji/NUL、注释/引号/反斜杠、未闭合/未知转义与后续入口恢复、64 KiB 接受/超限拒绝、独立 IR 总量上限。runtime 覆盖无效 UTF-8/长度、预算/取消、三级准入回滚和 GC/陈旧引用。真实 AOT 验证 initializer/fn/handler、跨帧根、GC/让出/失败清理与单/双 worker；保留原 CPU/墙钟/业务阶段。MVP、公平/故障、原生双平台及 BEAM 双门禁不因此完成。
