# ADR-0112：TCP 启动握手的有界失败证据

- 日期：2026-11-17
- 状态：已采纳（验证可靠性，不是运行时性能优化）
- 延续：[ADR-0048](0048-bounded-loopback-service.md) 的受限真实 I/O 验证和 [ADR-0110](0110-reproducible-bounded-workspace-validation.md) 的失败保留原则。

## 决定

真实 AOT 的 TCP 启动等待保留原 5 秒绝对 deadline，但从只等待第一次可读改为有界读取完整换行握手。最多接受 4096 字节，不允许半行让 `readline` 永久阻塞；验证 JSON 对象及字符串 listening 字段，后续仍验证 loopback 地址。使用无缓冲二进制管道，避免读握手时预读并丢失最终报告。

TCP 子进程独立进程组，CPU 20s/core 0 不变。启动超时、EOF、超长、非法编码/JSON/schema 均失败，不重试、不预热、不延长启动窗口。先保留清理前退出状态，再终止进程组/回收主进程，各管道只非阻塞读取最多 4096 字节证据；异常附耗时、退出码及 stdout/stderr 前缀，不能因管道持有者阻塞取证。清理不是继续执行业务的时间。

原场景、资源/队列/连接/帧容量、3 秒业务阶段、I/O deadline 和受管 ABI v21 均不变。失败不因后续成功自动消除，也不凭空把启动停顿归因给 VM 或宿主。

## 验证

独立 Python 回归覆盖正常握手不吞最终报告、静默/半行绝对 deadline、非零退出及两管道证据、空 EOF、非法编码/JSON/schema、超长/大 stderr 有界读取、持管道后代清理；CI 两原生平台运行相同入口。实际运行和失败保留见[验证记录](../validation-tcp-startup-2026-11-17.md)。

这不完成 TCP 间歇超时根因修复、完整资源账本、公平/故障、最新原生双平台或 BEAM 吞吐/整机内存门禁，不能宣布 MVP 完成。
