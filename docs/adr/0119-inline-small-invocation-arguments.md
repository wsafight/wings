# ADR-0119：小参数调用内联存储

- 日期：2026-11-18
- 状态：实验后回退（未建立端到端收益，仅保留诊断和冻结候选）
- 延续：[ADR-0080](0080-central-execution-admission.md) 的集中控制准入与原 4352 B 预留。

## 背景与候选方案（未采用）

原执行核心把非空参数复制到独立 Vec，再随 corosensei 闭包转入 guarded stack。受限单线程分配计数器实测：1/64 参数各 16 次真实 AOT 调用各有 16 次 Rust 分配，0 参数没有分配；这不是从 profile 推断的调用次数，也不包含 allocator/系统内部成本。

先尝试的固定 64 槽直接捕获超过 corosensei 当前实现的 1024 B 闭包传递界，实际 panic，未采用且保留失败。新内部 `InvocationArguments` 用 enum 保存 0..=8 个固定 i64 和实际长度，9..=64 继续原 fallible Vec，超过 64 直接拒绝。不增加依赖、不改 corosensei 或其保护边界。

候选参数仍在控制准入和借栈之后、移动 heap/Bytes 之前独立复制，初始化、同步、受控及 owned task 共用。导入只得到实际长度的可变 slice，不把未使用的固定槽作为参数或根；业务入口读取同一份已导入存储。挂起期间不借用调用方数组，不改变引用消息复制、精确根、取消、让出、预算、失败不提交和 Drop 正常返回。

候选不得因 enum 的固定控制空间或最大 fallback 参数而提高原 4352 B 预留，保留时须核对实际类型上界；本次在完整候选验收前已回退，不将未执行的候选测试记作通过。较小的分配次数不意味着减少执行预留或 RSS。ABI v21、manifest v2、执行栈、actor/mailbox/request/堆容量、CPU/墙钟和各阶段限制不变。

## 验证与取舍

隔离候选的受限分配探针在真实 AOT 运行 0/1/8/9/64 参数各 16 次，启动后覆盖调用方数组并逐步 `resume(1)`，核对挂起/回复/累计 state、每轮回到同一账面和最终启动基线；小参数零分配，大参数保持每次一次 fallback 分配。该局部分配证据不代替端到端验证。正式实现保留原 Vec，新增的独立诊断核对当前零参数不分配、非空每次一次，并接入完整原受限 AOT；不留下只为已撤回类型服务的单测或改变控制公式。

原 hot-queue 固定负载的独立冻结对照保留拒绝、超时、迟发及全部原始事件，不能因减少一次分配宣称持续吞吐或内存门禁通过。若没有稳定端到端收益，只能将结果描述为已验证的分配次数变化；有回归证据则撤回实现，保留探针和实验。最新原生双平台及同负载 BEAM 吞吐/整机内存双门禁仍独立验收。

实际失败与独立探针、冻结原始文件和最终验证见[记录](../validation-invocation-arguments-2026-11-18.md)。
