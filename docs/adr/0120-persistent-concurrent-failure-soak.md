# ADR-0120：持续 VM 内的双发送者失败生命周期长测

- 日期：2026-11-18
- 状态：已采纳（长时故障验证切片）
- 延续：[ADR-0092](0092-concurrent-failure-counter.md) 的 v9 失败前缀、有限准入与原 3 秒阶段；v9 输入、窗口和旧入口保持不变。

## 决定

v9 每次重建整个运行环境，不能覆盖持续运行中的槽复用和累计租约。新增独立 v10 容器入口，重复使用同一个 VM、模块、tenant、Scheduler 和 supervisor；BEAM 使用同一个 VM/驱动进程和已装载的业务/gate 模块。每轮创建新业务 actor，从相同初始 Bytes/binary 状态开始，两个真实发送者各窗口 16、各至多 128 请求，仍由独立 v9 前缀 oracle 检查合法交错及失败前的旧提交状态。失败/关闭不重试，不把重建称为自动监督恢复。

固定长测为 30 秒预热、60 秒采样、每 100ms 计划一轮，共 900 轮；迟发照实记录，不删轮、不提前结束采样。每轮仍最多 3 秒，整个业务阶段 120 秒、OS CPU 240 秒/墙钟 130 秒、禁 core。三轮独立 `--verify-soak` 用于普通 AOT 回归，原短业务 CPU 5 秒/墙钟 10 秒不变；它不是长测。只有显式长测入口执行 90 秒。VM/tenant 256 MiB、process 4 MiB、两 worker、32 结果槽、mailbox 32、原堆/栈容量与 4352 B 控制不变。

每轮必须同时有两条非空发送流、至少一个注入失败目标及实际健康目标业务。公共 Rust/BEAM 业务核心由 v9 和 v10 共用，避免两个版本的语义漂移。当前标准长测使用 3 actor、各 128 请求、sender delta 为 1/2、第 19 条向 actor 1 注入失败，另两个 actor 正常推进；state 为 256/4096/65536 B 之一，长度和原 32 B 提交前缀检查不冒充通用全状态导出。

## 清理、旧身份与原始记录

每轮收齐全部请求和每个 child/BEAM monitor 的终态，健康目标停止，failed child 已释放。Wings 等待 process/message/request 三维回到零；持续控制和最多每 worker 两个 guarded stack 缓存仍真实计费。以启动后的冷 Scheduler 账面及实测固定栈槽字节核对，仅允许 0..=4 个完整槽的差额，不能把缓存说成没有内存成本。退出整个持续环境后必须精确回到非零根启动值；allocator/系统内存另行验收。

记录中的 `cached_stacks` 是上述逻辑差额除以槽字节的推导值，不是对各 worker 映射/缓存的独立普查；符合这个有界等式仍不能证明不存在所有可能的同尺寸漏计或存储问题，完整资源与内存门禁不据此闭环。

本轮终止后、下一轮新目标仍存活时，都验证上一代完整 Pid/child ID 的查询和 send/request 拒绝；两代不能出现相同完整 Pid。BEAM 核对旧 actor 已死、旧 CAS gate 保持关闭并拒绝投递；原生无界发送不能代替准入。

每轮原始 JSONL 包含计划/实际开始/完成时刻、旧身份检查数、各输入结果、每目标提交值/序号/失败和保留账目。固定 64 KiB 写缓冲、64 MiB 文件上限，独占创建，不覆盖旧文件；不在 runner 中累计无界历史。长测驱动冻结源码、runner、输入、产物和 oracle，并在每端前后核对 hash；独立逐行重放，拒绝缺失/重复轮次、假失败/回复/前缀、短采样、超出 3 秒、旧身份漏检、错误缓存/计费和非完整原始行。失败时保留部分 trace、控制输出、错误及 invalid manifest，不盲目重跑。

## 边界与验证

默认 AOT 只跑三轮 Wings/模型；真实 OTP 29 对照须 `--compare-beam`，缺少即失败，无模型回退。验证三种 state、相同 Scheduler 的槽复用、当前/前代拒绝、完整请求前缀/清理、非法 workload、trace 独占与容量、驱动失败证据保留及伪造历史。debug/release、check/clippy/fmt/MSRV 与最新原生双平台仍分别运行。

这是持续失败生命周期证据，未加入长时 timeout/cancel、自动重启强度、过载竞争或服务 I/O。单轮固定负载不是持续吞吐；缺少 CPU 硬配额、完整平台内存/监测偏差、主机隔离或最新原生双平台时，不宣布完整故障、公平、BEAM 双目标或 MVP 通过。ABI v21、manifest v2 和语言语义不变。
