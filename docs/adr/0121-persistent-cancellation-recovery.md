# ADR-0121：持续 Scheduler 的取消与监督恢复验证

- 日期：2026-11-18
- 状态：已采纳（既有恢复语义的持续验证）
- 延续：[ADR-0074](0074-bounded-concurrent-recovery.md) 的取消/超时不撤回、stop 竞争和一次重启强度限制；补充 [ADR-0120](0120-persistent-concurrent-failure-soak.md) 尚未覆盖的恢复生命周期。

## 决定

将原 `concurrent_recovery` 的单轮业务抽为可重复步骤，同一 Scheduler/supervisor 内复用固定两个 actor 槽。每轮仍为 4 KiB Bytes、两个发送线程各八条 Add、mailbox 16、共享结果 17、一/双 worker 和同一三秒绝对期限。四条请求立即超时、四条先取消，余下八条与 stop 竞争；已消费结果不能复活，publisher 完成前不能释放原请求容量。健康目标必须正常提交 +7。

停止不重启。随后新 child 的两个已取消 Fail 消息仍实际执行、报告除零并保留旧提交零状态；第一次全新 heap/state 重启，第二次强度超限。保留原一次/60s 的政策；显式创建的新 child 有自己的历史，不把每轮创建说成自动恢复。每轮后、下一轮新目标仍活着时验证前代 Pid/child ID 拒绝，防止槽复用复活旧身份。

原默认入口保留每配置一轮；新增普通 `--verify-reuse` 每配置三轮，显式 `--soak` 才执行 30s 预热/60s 采样、每 100ms 一轮共 900 轮。迟发不跳轮；每轮三秒、整体阶段 120s，CPU 240s/墙钟 130s/core 0。普通短子进程 CPU 5s/墙钟 10s；完整 AOT 原 CPU 20s/墙钟 30s 不变。VM/tenant/process 原 128 MiB 与所有运行时容量不变，根改用实际计费构造，最终回到非零启动基线。

原始 JSONL 记录每条请求的单一结果、队满拒绝/原预留、健康提交、两次失败/重启/初始状态、计划/开始/完成时间和账目。固定 64 KiB 缓冲、64 MiB 文件上限，独占创建；独立重放拒绝缺轮/超时/假终态/错误重启和清理。复用 ADR-0120 的受限子进程捕获，失败保留 stdout/stderr、部分 trace 和 invalid manifest；冻结源码/输入/产物并前后校验 SHA，不重试来抹掉失败。

## 账目与边界

每轮 process/message/request 为零，逻辑余量仅允许冷 Scheduler 基线加每 worker 至多两个固定 guarded stack 槽。缓存数由账面差额推导，不是独立映射普查；最后环境释放回根启动字节。原始状态快照仍只验证完整长度与 32 B 前缀，不冒充通用全状态导出或完整资源账本。

独立模型须拒绝伪造状态、遗漏请求、重复消费、撤回失败、错误重启强度、旧身份漏检和资源残留。真实 AOT 分别验证一/双 worker；ABI v21、manifest v2、语言和运行时实现不变。没有 BEAM 等价恢复协议、长时过载/服务 I/O、公平性或吞吐/整机内存结论；最新原生双平台和 MVP 门禁保持独立。
