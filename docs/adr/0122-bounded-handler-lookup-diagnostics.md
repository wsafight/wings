# ADR-0122：宿主 handler 名称查询的有界错误来源

- 日期：2026-11-18
- 状态：已采纳（资源拒绝路径修正）
- 延续：[ADR-0091](0091-manifest-string-preflight.md) 的来源有界原则；修复宿主查询入口而非改变清单或语言名称。

## 问题与决定

`ScalarModule::handler(name)` 对未命中的名字使用 `format!("unknown handler {name}")`。清单和 CLI 已限制名称，但直接宿主 API 仍可传任意长字符串；即使 process/tenant/VM 已满，错误构造也会按外部输入重新分配。真实独立分配计数器复现 3145728 B 输入生成 3145744 B 错误和同尺寸分配，先于任何 handler 执行。

查询前沿用清单名称的同一规则：非空、至多 256 UTF-8 字节、无控制字符；不合格返回固定 `invalid handler name`。规则由产物库公开为 `valid_name`，VM 和 CLI 直接复用，避免重复常量/判断漂移。合法但未知的名字保留原 `unknown handler {name}`，最大错误为 272 B；合法已存在名字的成功路径不分配。以字节计长，完整多字节边界保留，不截断 UTF-8。

错误仍是宿主拥有的 `String`，固定有界错误没有伪称已由 process 计费；消除按恶意输入放大的分配不等于所有诊断/装载器/allocator 已纳入完整账本。不改变名称合法集合、源码类型拼写、业务状态、受管 ABI v21、manifest v2、4352 B 或任何额度。

## 验证

保留修复前实际大分配失败；在受限 OS 子进程内分别让 process/tenant/VM 精确满额，核对直接模块查询和经进程调用的空名、256/257 B、UTF-8 256/258 B、换行/NUL/DEL 与 3 MiB 名字。非法路径固定错误、合法未知名字保留原诊断，任何一次请求的最大分配不超过 1024 B，错误不超过 272 B；验证原账户不变、已提交状态仍为 +7、解除满额后可继续查询及最终根清理。

单元测试验证名称规则和成功查询零额外分配，真实 AOT 覆盖模块及进程。完整 check/clippy/fmt、debug/release、MSRV 与原生双平台分别执行；交叉检查不是原生运行。来源有界不代表系统 OOM 可恢复或 MVP 已完成。
