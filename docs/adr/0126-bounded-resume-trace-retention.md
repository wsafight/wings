# ADR-0126：恢复历史满额后保留业务、显式丢样

- 日期：2026-11-18
- 状态：已采纳（有界诊断保留，仍非公平性门禁）
- 部分替代：[ADR-0125](0125-streamed-resume-fairness-diagnostics.md) 的 v12 历史满额即终止；原 v12 入口与失败证据保留。

## 背景

首个本机 v12 长测在约 51.65s 触及 8000000 条恢复事件上限，正确返回 oracle_error，五次计划停在第一轮。原文件、冻结源码/程序、环境、stderr 与进程采样保留 `target/resume-fairness-macos-20261118/`。这证明原事件预算不足以保留本机整段历史，不能提高上限、删除失败或把半段采样称为通过。

## 决定

新增独立 `--measure-slices-bounded`，输出 v13。原 8000000 条、512000000 B 协议文件上限、1024 FIFO、业务/片预算/quantum、30s/60s 与 CPU/墙钟限制均不变。达到事件保留上限后，宿主继续消费 FIFO，但不再写恢复记录，独立累加 `trace_dropped`；心跳/热任务和原子请求事件继续按原协议完整记录。固定内存、不覆盖旧值、不扩大额度。

结束报告 `trace_limit`、`trace_emitted`、`trace_dropped`，与 observer 的 FIFO dropped/taken 分开；计数溢出使实验失败。核对 `observer.taken = trace_emitted + trace_dropped`、`published = observer.taken + FIFO dropped`，原三种结果总数仍覆盖全部实际恢复返回。v12 仍保持满额失败，v13 不回写它的结果。

独立重放核对文件记录、内部序号缺口和尾部缺口，区分 FIFO 与历史保留两类丢样；收到最终统计后，在保留前缀末端关闭后续业务时钟配对并释放有限关联表，不能为缺失历史无限保留业务请求。原业务流仍完整核对 900000 次计划、实际结果和状态。没有丢样时保持原全部逐次配对；有丢样时明确 `complete=false`，只报可观察子集、最后保留时点与前缀配对数，不将其分位冒充整个采样窗。

## 验证与边界

保留 v12 实际失败与独立模型，新增历史满额、两类丢样拆分、前缀关闭、计数伪造与零丢样模型。新 v13 使用新目录、冻结新协议后重新测量，不将其称为原 v12 重试；原始失败不覆盖。默认完整 AOT 仍不自动跑 90s 长测。

v13 能完成业务不等于有完整恢复时间分布；历史或 FIFO 缺样均不能通过完整公平性门禁。后续若需要整段精确分布，须另行设计外部聚合/编码或有界分布统计并验证其误差与开销。CPU 硬配额、过载分组、原生双平台与 BEAM 双门禁不变。
