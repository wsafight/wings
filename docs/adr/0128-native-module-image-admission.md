# ADR-0128：原生模块映像跨度先准入

- 日期：2026-11-18
- 状态：已采纳（模块账本切片；验证结果另记）
- 后续：[ADR-0129](0129-native-module-dependency-boundary.md) 限制额外依赖旁加载，保留本决定的单映像预算与最后 owner 清理。
- 部分替代：[ADR-0044](0044-native-module-leases.md)、[ADR-0085](0085-module-path-admission.md) 仅按库文件大小预留库页的规则；控制先准入和代码租约不变。

## 原因

文件长度不等于装载映像跨度。本机普通 Counter 产物为 17344 B，原库页票据 20480 B；Mach-O 的 `__TEXT`/`__LINKEDIT` 各占 16384 B，跨度为 32768 B。旧回归在 2 MiB 控制预算外只核对文件页，会漏掉这 12288 B 的映像容量。此处不是 RSS 测量，也不声称这些页全部驻留。零填充段与段间空洞同样不能按文件长度估计。

## 决定

- `load_accounted` 仍先预留原 2 MiB 控制预算，再解析路径、查询至多 64 MiB 的普通库文件，预留按原 4096 B 取整的文件预算并校验清单。在文件票据保护下用 fallible 预分配读取固定长度快照；不使用可能放大缓存的流式对象解析器。
- 复用锁定依赖 `object 0.36.7` 的原始 ELF64/Mach-O64 头部与段表读取，不接入代码生成、压缩或通用对象图解析。遍历本身不创建段/节向量；截断、错误段范围、非动态库、空映像和地址/取整溢出均在动态装载前正常拒绝。
- ELF 取 `PT_LOAD`，Mach-O 取 `LC_SEGMENT_64`，包括零填充区；按照当前 OS 页大小对齐各段端点，用最低起点到最高终点的整个跨度计费，包含空洞，重叠段不重复累加。映像跨度独立限制为 64 MiB，不提高原文件、VM 或执行额度。
- 快照释放后才追加不足的映像票据并调用动态装载器。常驻预算为 `2 MiB + max(原文件页, 映像跨度)`；文件快照与装载映像不会同时持有，不为二者重复预留。追加失败不调用装载器；临时存储、解析和加载/符号错误均回到调用前账目。
- clone、handler、实例及活栈共持一次租约；独立加载仍独立准入。最后代码 owner 交还 `Library` 后归还全部票据。可信产物不可在校验至加载期间修改；非计费 `load_trusted` 兼容入口、ABI v22 与 4352 B 控制预留不变。

映像预算是 VM 逻辑容量，不是 dyld/ld.so 内部开销、依赖库的递归总计、allocator 元数据、RSS、PSS 或物理占用。不提供不可信 native 文件沙箱、热更新或完整 OS 资源隔离。

## 验证

保留修复前普通 Counter 的文件/段/页大小与旧账目。两个平台格式的合成头部在受限测试子进程内覆盖零填充、空洞、重叠、页取整、错误范围、截断、溢出及上限；合成损坏产物不进入动态装载器。真实 Counter 覆盖精确预算、少一字节、第二次加载拒绝、最后 owner、挂起取消和失败退账；完整 AOT 增加与编译器产物同源、扩大映像而不扩大文件的静态只读 fixture。按原限制执行 workspace、MSRV、平台交叉检查和 Debug/Release AOT，原生双平台与 BEAM 双门禁仍独立验收。
