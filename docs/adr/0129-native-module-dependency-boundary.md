# ADR-0129：计费模块的原生依赖边界

- 日期：2026-11-18
- 状态：已采纳（模块账本切片；验证结果另记）
- 补充：[ADR-0128](0128-native-module-image-admission.md) 的单映像准入；不是递归原生包管理。

## 原因与选择

单库映像准入不覆盖依赖库。原编译器经 `CC` 重链的 Counter 可以额外声明一个不被业务访问的只读零填充 dylib，主库仍只预留 2129920 B，却由 dyld 旁加载另一个含 1 MiB 零填充的映像；旧精确预算回归通过。这符合现有可信 ABI、不依赖可变 native globals 的要求，不靠不可信机器码或构造器。

MVP 不支持任意 native 扩展，也没有可计费的递归依赖解析/装载器。因此选择限制计费产物的依赖，而不是漏计、任意扩大固定预算，或实现另一套原生动态装载器。

## 契约

- 仅对 `load_accounted` 执行，沿用 ADR-0128 的固定文件快照及先准入规则，不新增分配向量或改变 ABI v22。`load_trusted` 保持显式非计费工具兼容入口。
- Mach-O64 仅允许普通 `LC_LOAD_DYLIB` 指向精确的 `/usr/lib/libSystem.B.dylib`；弱/延迟/向上/重导出依赖和其他路径均拒绝。拒绝 rpath、自选 dylinker、旧 FVMLIB/prebound 及 dyld environment 指令，库自身 ID 不视为依赖。
- ELF64 无依赖或只声明精确 `libc.so.6` 可接受；动态表必须唯一、有终止项，依赖名称必须在唯一文件后备 PT_LOAD 中的有界动态字符串表内。拒绝解释器、filter/auxiliary/audit/depaudit 和 rpath/runpath，避免其他隐式加载渠道。未知业务依赖和坏字符串正常拒绝，不打印产物控制的任意长名字。
- 检查失败在 `Library::new` 前返回并释放文件/控制票据；不访问依赖路径、不加载依赖、不执行 native 初始化。允许的系统运行库属于宿主平台基线，仍须纳入整机内存实测；不声称其物理成本为零。
- 调用者仍保证可信产物不变以及宿主装载器环境可信；`LD_PRELOAD`/`LD_LIBRARY_PATH`、`DYLD_*` 等宿主策略不是本进程内机制的安全边界。basename `libc.so.6` 也不是签名、真实来源认证或 OS 沙箱。

现有默认编译器、原资源/时间限制、代码租约和清理顺序不变。若未来需要系统额外库、可信 native 内建或第三方依赖，须新增依赖清单、来源/生命周期和完整计费契约，不直接放宽此规则。

## 验证

保留修复前真实只读依赖回归。两种格式/端序合成表覆盖允许项、未知库、重定向、弱/延迟加载、截断/重复/缺终止/错误名称范围，在受限测试进程内检查，损坏表不动态加载。真实 AOT 产物声明有效的额外只读依赖时，应明确因不支持依赖而拒绝并精确回到基线；正常 Counter、缺符号、原映像 fixture、挂起取消和末 owner 回归保持。原生双平台与 BEAM 双目标仍独立验收。
