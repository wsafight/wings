# ADR-0132：多 actor 对照的有界 I/O 与失败证据

- 日期：2026-11-18
- 状态：已采纳（验证宿主修正；不代表启动超时根因已修复）
- 补充：[ADR-0063](0063-multi-actor-byte-counter.md) 的 v2 验证宿主；沿用 [ADR-0112](0112-bounded-tcp-startup-evidence.md) 的有界失败证据原则。

## 问题与决定

本轮完整 Debug AOT 的 `verify_multi_counter.py` 在原十秒子进程期限超时。旧 `communicate` 在退出后才检查 stdout 1 MiB/stderr 64 KiB 上限，超时清理时又丢弃已收输出；外层仅知道命令，没有用例身份或请求指纹。该次失败仍保留于 [BEAM 恢复记录](../validation-beam-recovery-2026-11-18.md)，不能用后续成功覆盖。

以非阻塞 selector 同时推进有限输入和两个输出流，从读取时即限制各自保留容量；不等待完整输出后才限额。输入最多接受 65537 B，以保留原 65536 B JSON 边界的多一字节拒绝用例；stdout/stderr 仍为原 1 MiB/64 KiB，业务 CPU 5s/墙钟 10s/core 0 不变。标准输入、管道读写、EOF 后进程等待共用同一个绝对单调期限，单元测试只能缩短此期限。进程结束但后代仍持输出管道也不能越过该期限；失败终止整个自建进程组，关闭本次所有管道。

调用器中的 I/O、进程等待及 JSON 解码异常保留固定 JSON 错误：有限命令/用例标签、输入长度/已写长度/前 40 B/完整 SHA、观察到的 stdout/stderr 字节数、EOF、各前 1024 B、前缀是否截断、清理前后退出值及实际耗时。字节数只称已观察，不声称等于未读部分或远端已消费输入。标签区分正常用例编号/runtime/actor 数/state 长度，以及非法桥接/JSON 的编号；结合冻结源码可重建同一输入，不增加业务输出或修改 VM 协议。无法解码的输出以转义前缀保留，非零合法协议退出仍原样返回；外层业务 oracle 的断言保持。

验证宿主仍是可信本机工具；此修正没有新增原生栈采样、自动重试、吞吐测量或系统配置，不把有输出与无输出的失败推断成某个 runtime 阶段。OS 创建进程和外层运行器的更广生命周期继续独立验收。本次只收敛可轮询子进程 I/O、保留失败和进程组清理；完整账本、原生双平台、启动根因与 MVP 门禁保持未完成。

## 验证要求

新增七项真实受限子进程测试：完整输入回压、正常/合法非零协议退出、带双流前缀的超时、双流 EOF 后仍不退出、输出越界时提前停止、错误 JSON/UTF-8/stderr，以及退出 parent 的持管道后代清理和期限/输入上限拒绝。所有临时 marker 位于独占测试目录，不注入崩溃、非法访存或 OOM。默认 CI 增加该短入口；实际 BEAM 对照仍显式启用，原阶段和容量不变。实际结果见[验证记录](../validation-multi-counter-evidence-2026-11-18.md)。
