# ADR-0136：计费模块使用固定原生路径缓冲

- 日期：2026-11-18
- 状态：已采纳（模块暂存账本切片；验证另记）
- 延续并部分替代：[ADR-0135](0135-bounded-accounted-module-paths.md) 的计费路径 canonicalize 实现

## 问题

0135 已阻止超大原始路径的 Rust 副本，但 `std::fs::canonicalize` 返回的拥有型路径在长度检查前分配。只检查最终长度没有为这个输出提供明确的分配前边界。可信工具行为不需要随计费入口一起收紧，也不应自研文件系统或符号链接解析。

## 决定

保留原 VM 类型检查和 2 MiB 模块控制准入，原始路径仍至多 16 KiB、按原生编码字节计数。在计费入口用固定 16385 B 栈缓冲暂存 NUL 结尾来源，先拒绝嵌入 NUL，再调用平台 `realpath`；提供调用者持有的 `PATH_MAX` 输出数组，不使用要求 libc 分配结果的空输出指针。macOS/Linux 的原生路径限制不提高，系统错误保留。

成功结果必须来自提供的数组、在数组内 NUL 结尾且为绝对路径；然后才按已知长度一次 fallible Rust 分配构造拥有型路径，要求请求容量不被扩大。原输入/输出暂存与结果副本的最大逻辑容量包含在原模块控制预留中，不增加预算、不提高文件/映像或执行上限。工具入口 `load_trusted` 继续使用标准 canonicalize；ABI v22 和 4352 B 不变。

这关闭调用者可控的 Rust 来源和输出副本的容量边界，不把原生 `realpath` 内部 scratch、libc/动态装载器/allocator 元数据或宿主线程栈说成已经逐项测量或全部计费。可信产物在验证与装载期间不可变的原前提不变，也没有新增竞态安全或 OS 隔离承诺。

## 验证与回退

边界测试核对来源超限/NUL 在调用原生 resolver 前拒绝、空/恰好上限/非 UTF-8 来源、无终止/非绝对结果、原生失败及最大合法输出。原生临时目录核对相对路径、符号链接、非 UTF-8、缺失和循环链接与标准 canonicalize 的结果。原十二场景分配探针、正常加载及错误模块、Debug/Release 全量 AOT 和 workspace 回归继续使用原限制；MSRV、交叉编译和原生平台分开记录。

回退只回到 0135，不能恢复其已阻止的超大来源副本。完整资源账本、启动稳定性、公平/故障、原生双平台和 BEAM 双目标仍独立验收；本切片不称 MVP 通过。
