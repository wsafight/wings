# ADR-0139：模块清单的普通文件读取边界

- 日期：2026-11-18
- 状态：已采纳（模块输入与资源边界切片）
- 延续：[ADR-0128](0128-native-module-image-admission.md)、[ADR-0136](0136-fixed-buffer-native-module-paths.md)

## 缺口与决定

共享 `Manifest::read` 原先直接打开 `manifest.json`，再限制最多读取 65537 字节。字节上限不能限制打开 FIFO 等待写端的时间：修改前的真实 VM 在受限子进程三秒墙钟内没有结束，原生采样停在 Manifest::read → File::open → open；普通清单和指向普通清单的符号链接都能执行 Counter。该复现不是既有 TCP/dlopen 启动超时的根因证据。

在共享读取入口打开文件前检查解析后的文件元数据，只允许普通文件且长度至多 64 KiB；打开后再检查实际文件句柄的类型和长度。继续接受指向普通文件的符号链接，拒绝目录、FIFO、socket 和指向这些对象的符号链接，不给 artifact crate 增加原生依赖。清单路径仍固定为所给目录下的 manifest.json，不接受清单指定其他文件。

按句柄报告的已验证长度使用 fallible 精确预留并读取，随后探测一个额外字节；截断、读错误或增长均失败，不通过不断扩容接受变化文件。原有 JSON 预检、语义校验、64 KiB 边界、2 MiB 模块控制预留、映像预算、ABI v22 和 4352 B 执行控制保持。计费模块仍先预留控制/库预算，拒绝后沿原租约退账。

## 信任与验证边界

产物及其路径在验证和装载期间保持不变，沿用可信静态 AOT 前提。两次元数据检查不构成恶意并发替换防护；检查到打开之间被改成 FIFO 仍可阻塞。普通文件所在文件系统也可能发生 I/O 等待，本决定不承诺加载墙钟上界，不引入后台线程、取消机制或不可信文件系统沙箱。

验证覆盖普通/精确 64 KiB/超长/空/损坏清单、目录、FIFO、Unix socket，以及普通/悬空/特殊目标符号链接。会阻塞的旧版复现只在 CPU/墙钟/core 受限子进程内运行并保留可执行副本、输入身份、双流、退出和采样；新版检查真实 CLI、计费/工具加载、成功执行及拒绝后精确退账。完整 workspace/AOT 与工程检查继续执行，保留原失败，不将本切片称为完整账本、启动稳定性、原生双平台或 BEAM/MVP 门禁通过。
