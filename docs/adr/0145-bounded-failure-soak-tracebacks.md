# ADR-0145：失败长测验证的有界异常来源

- 日期：2026-11-19
- 状态：已采纳（失败诊断补充；EPERM 根因未定）

## 背景

push 流水线 `44477376615` 的 macOS Debug AOT 在 `verify_failure_soak.py` 返回 `[Errno 1] Operation not permitted`，同提交 PR 流水线通过。顶层处理只打印异常字符串，无法区分子进程 `setrlimit`、进程组清理、内存普查或其他 OS 调用。没有具体调用位置就不能提出可信修复，也不能用 PR 通过覆盖 push 失败。

## 决定

- `verify_failure_soak.py` 的既有异常类型与 exit 3 保持不变，失败时额外输出 Python traceback、异常类型和因果链。
- traceback 最多保留 12 层；编码后超过 8192 B 时保留首尾并插入显式截断标记，避免任意长异常消息无限扩张 CI 诊断。截断按 UTF-8 字节边界解码，丢弃不完整的边缘字符。
- 成功路径、模型核对、真实 Wings/BEAM 子进程、资源限制、输出上限和三秒轮期限均不改变。该诊断不吞掉原异常，不自动重试，也不把权限错误归类为 VM 故障。

## 范围与限制

这只是下一次间歇失败的取证入口，尚未在本机复现 CI 的 EPERM，更没有证明它来自某个特定系统调用。新增测试只验证来源、因果链和有界编码，不验证权限错误根因。完整并发故障、长时过载/服务 I/O、原生双平台和 BEAM/MVP 门禁保持开放。实际验证见[记录](../validation-failure-soak-diagnostics-2026-11-19.md)。
