# ADR-0149：CFG 边 phi 与精确引用根计划

- 日期：2026-11-20
- 状态：已采纳（M0 内部根分析切片）
- 补充：[ADR-0025](0025-aot-record-roots.md)、[ADR-0033](0033-record-conditional-roots.md)、[ADR-0034](0034-record-state-loops.md) 的精确根发布契约；替代其线性最后使用与分支恢复快照的根集合计算方式

## 背景

条件合流和 state 回边已经由 Cranelift 块参数实现，但 `wings-ir` 仍以线性最后使用位置、进入分支时的根快照和循环范围延长计算根。连续合流会把未选中路径的值保守留到检查点，嵌套控制流也依赖多处特判。后续动态调用根链需要以实际 CFG 活跃度为准，不能继续叠加路径修补。

## 决定

- 只在 `wings-ir` 内把已验证的结构化指令镜像为与 codegen 同构的 CFG。普通指令各占一个程序点，另建 after-else、after-loop 和最终虚拟节点；不增加源码语法、IR 跳转或 phi 指令，不改变现有寄存器作用域和验证规则。
- `If/Else/EndIf` 的两条合流边分别携带所选值，`Loop` 入口携带初始 state，`EndLoop` 回边携带下一候选，`While` 假路径把当前 header 值带到 after-loop。边输入只在该前驱路径计入活跃度，不能因另一臂定义或使用某个寄存器而将其发布到当前路径。
- 对引用类型执行反向 liveness 不动点计算。节点的入口需求为普通操作数及后继入口需求减去本节点定义；边 phi 输入计入对应前驱的 live-out。`Loop` 和 `EndIf` 的块参数在各自检查点前定义并发布，`EndLoop` 结果只在 after-loop 定义，不能提前占用回边检查点根槽。
- `RootPlan.at` 继续描述 codegen 每个原 IR 检查点之前应发布的精确引用集合，最终点保留候选 state 与回复；虚拟节点只参与数据流，不增加预算、检查点或业务操作。容量取所有真实检查点的最大根数，仍受每函数 64 根限制。
- `RootPlan.last_uses` 暂按原线性算法保留，只用于现有兼容诊断和测试，不再决定根准入、容量或 codegen 发布。后续删除该公开内部字段须单独核对调用方，不在本片混入。
- ABI v22、`ScalarContext`/shadow frame 布局、Cranelift lowering、强制预算/取消/让出检查、GC、资源额度和产物格式均不变。没有新的 runtime 根来源，也不改变候选提交和失败语义。

## 验证与边界

IR 回归逐项核对边 phi、连续合流、未选中临时值回收、嵌套分支/回边、引用 state 的零次循环出口及最终候选根。真实 AOT 扩展 `record-loops`，由独立 ctypes 宿主在每次 heap 和 slow-path 回调前强制收集，覆盖连续合流全部路径、嵌套回边和零次循环；同时保留已有记录、列表、字节、字符串、函数帧及失败清理回归。

两种构建的全目标测试和原限完整 AOT、MSRV、Linux x86-64 检查分别记录，不能用单测或定向 AOT 替代。该片只统一已有结构化控制流的根分析，不开放任意 CFG、递归、前向调用或动态派发，也不完成动态调用根链、完整资源账本、公平/故障长测或 BEAM/MVP 门禁。实际结果见[验证记录](../validation-cfg-reference-root-plan-2026-11-20.md)。
