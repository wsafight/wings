# 激进优化

[文档目录](../docs.md) · [项目概览](../README.md)

这些方案用于尝试在相同负载下取得高于 BEAM 的吞吐和更低的内存占用，没有预设的加速倍数。当前未发布标量源码已有专用整数运算、共享只读模块和有界栈池等局部切片，不代表下面完整候选已实现，更未证明领先 BEAM。默认设计见[架构设计](architecture.md)、[运行时](runtime.md)和[语言设计](language.md)。

## 实验约定

- **优先实验**：不改变语言语义，开启和关闭优化分别与正确性基线比较。
- **条件实验**：需要证明类型、所有权、大小或局部性满足条件，否则使用通用路径。
- **独立设计**：涉及 GC、受管 ABI、执行模型或后端变更，先修改设计再实现，不作为首版默认方案。

实验前写清要解决的瓶颈、预期收益、依赖条件、风险和回退方式，再按[评测协议](evaluation.md)测量。macOS AArch64 与 Linux x86-64 分别验收；平台专用优化之外，保留另一平台可运行的路径。

## 编译与值表示

### 1. 类型特化、拆箱与直接分派

**优先实验。** 对可推导类型的整数、浮点、布尔、tag 和定长记录生成专用代码，避免统一装箱和动态标签分派。按消息 tag 直接进入专用 handler，把模式匹配编成判定树或跳转表。

跨越多态边界时保留统一值表示，整数溢出、相等性、浮点 NaN 和错误行为不能改变。限制特化数量，同时测代码体积、指令缓存和编译耗时，确认小样例的收益是否值得增加代码量。

### 2. 紧凑标签值与压缩引用

**条件实验。** 比较 tagged word、紧凑对象头、相对 arena 基址的 32-bit 偏移与普通宽引用。NaN boxing 是浮点表示的一种候选方案，是否有足够的剩余位容纳指针，需要逐平台确认。

压缩引用必须定义范围、对齐、tag 和溢出路径；单窗口装不下时使用分段或宽引用，不能截断地址。压缩只作用于内部对象表示，不随意缩减 Pid 的 generation；对解引用检查和根枚举的额外成本单独测量。

### 3. 逃逸分析、标量替换与临时区域

**条件实验。** 把不逃逸的 tuple、记录和中间匹配结果拆成 SSA 值；只在本次 handler 存活的对象使用短命区域，在返回时批量回收。

进入 state、消息、请求或内建持有根的对象，不能再引用已释放的临时区域。晋升、复制或回退都在预算内完成；抢占时保存所有活跃标量与引用，优化后的引用仍须由 shadow stack 正确记录。

### 4. 尾调用、内联与跨过程优化

**优先实验。** 在受管 IR 做常量传播、去虚拟化、尾调用消除、内联和跨 handler 公共逻辑优化。已知 schema 的长度与形状检查可合并，但必须有控制流和整数溢出证明。

尾递归转为循环后保留抢占点，内联生成的长直线代码也要满足检查间隔。跨模块内联与代码版本、schema 绑定，升级时将其失效或重新编译，避免调用已回收的代码。

### 5. Profile 引导与目标机器特化

**条件实验。** 根据真实负载优化分支、消息 tag、对象布局和冷热代码布局，生成通用版本与特定 CPU 版本。runtime 的 Rust 部分单独评估 LTO/PGO；受管代码的 profile 驱动优化先在自有 IR 实现，Cranelift 是否具备所需的完整 PGO 支持需要另行验证。

SIMD 优先用于 codec、扫描与有界批量操作。目标特性写入产物，在装载前校验；测试也要覆盖训练数据以外的回退、首次启动、代码体积和浮点语义。开发机的 `native` 编译产物不能直接作为可移植发行物。

## 进程、堆与 GC

### 6. PCB 冷热拆分与惰性元数据

**优先实验。** 热部只保留寻址、状态、调度和当前 state 必要字段；links、monitors、请求表、诊断与迁移数据按需分配。没有关系或消息的进程不预建空容器。

比较 AoS、SoA 与分层槽表，避免为每个稀疏 PCB 填充整条 cache line。slot 复用仍校验完整 generation，惰性分配仍执行资源准入；测随机查找、退出和监督 fan-out，而不只测空进程数量。

### 7. 小 state 与小消息内联

**优先实验。** 为少量标量 state 和小 envelope 设计内联表示，省去一次间接访问和分配；超过阈值转为 arena 对象或独立消息缓冲。

根据负载分布选择阈值，避免为少量大消息扩大所有 PCB。PCB 搬移后不能留下失效的裸指针；状态迁移、GC、冬眠和 mailbox 编码都要处理内联与非内联两种表示。

### 8. worker 本地 slab 与 bump 分配

**优先实验。** 按尺寸分级复用进程堆块、消息和控制记录；已取得的进程专属堆块内使用 bump 快路径。跨 worker 释放走有界远程回收队列，减少全局分配器竞争。

worker 池缓存和空闲碎片都计入 VM 总内存，设置缓存上限，在内存压力下回收，避免分配次数减少却长期占用更多 RSS。微进程迁移时，两个 worker 不能同时写原 arena；内存不足仍走受管错误路径。

### 9. 不可变对象的唯一所有权复用

**条件实验。** 编译器或运行时证明旧版本不再被 state、共享结构、消息、原生内建或诊断持有时，可以复用其存储实现更新，减少持久化结构的复制。

复用只改变内部存储，不改变不可变值语义。无法证明唯一所有权时就复制；handler 失败时，尚未提交的旧 state 不能已被别名改写。重点验证共享子图、异常路径，以及提交前哪些变化可被观察到。

### 10. 按生命周期释放与分代回收

**条件实验 / 独立设计。** 先尝试临时区域与存活率引导的堆块分类，再评估小型 nursery、复制式年轻代、对象年龄和分代 GC，以减少完整堆扫描。

M1 仍用精确、非移动 mark-sweep。引入复制或压缩前，要修改 GC 模型，处理所有根、内建持有的引用、跨代记录、写入协议与固定对象。业务值虽然不可变，runtime 仍会写入；测试需报告总 CPU、临时双份内存的峰值和最大停顿。

### 11. stack map 替代高频 shadow stack 写入

**独立设计。** 当根发布成为热点时，评估后端精确 stack map，或只在可能分配、切换的位置发布必要根。相同根值的冗余写可在明确的 safepoint 区间内消除。

根位置必须覆盖寄存器、spill、内联和异步内建，相关元数据与代码版本一同保留。在两个平台分别验证后端能否提供这些信息，不能改用保守扫描或猜测原生栈指针来替代。

### 12. 热 / 温 / 冷状态分层与自适应冬眠

**条件实验。** 按 state 大小、空闲时长和历史唤醒率选择保留 arena、紧凑编码或冷 blob 压缩。压缩只针对已返回 handler 的 Idle state，采用有界分块算法。

压缩、索引、临时双份内存和唤醒 CPU 都计费，设置最短空闲时间、冷却期和唤醒预算，避免反复压缩与恢复。与 BEAM 冬眠分别比较时，要区分 macOS 的页面压缩和 VM 自身的节省。

### 13. 稀疏页整理、回收与大页

**条件实验。** 优先将新分配集中到少量 slab，在全空页上归还物理页面；比较按需提交、预触页和大页策略。初版不为页整理移动仍被引用的对象。

分别验证 Linux 与 Darwin 的回收、discard 和重用语义，只丢弃能够从确定数据重建或已不再存活的页。使用实际页大小；大页只在实测有利的密集区域启用，避免增加百万小 state 的驻留内存。

## 消息与资源快路径

### 14. schema 专用 envelope 与直接解码

**优先实验。** 为已知消息类型生成布局、大小计算和边界检查，减少通用序列化层与临时缓冲；小消息内联，大消息批量复制，接收者取得唯一执行权后直接解码到自己的 arena。

进程间不传裸引用。发布 envelope 前完成额度准入和完整性校验，限制接收端展开后的大小、元素数量与深度；保留通用 codec，用于回退和差分测试。

### 15. 只读 blob 共享与所有权转移

**条件实验。** 大型不可变 binary 在 VM 内共享，消息只携带受控句柄；独占且无外部别名的消息块可评估转移所有权，减少复制。

物理分配只记一次，逻辑持有额度按契约记账。转移前预留目标额度，跨级预留失败时整体回滚；退出、取消、冬眠和发送失败都不能泄漏资源。发送者 arena 中的对象不能任意交给接收者 GC，跨进程引用计数和集中释放的成本也要测量。

### 16. 分段 MPSC mailbox 与批量入队

**优先实验。** 进程只在有消息时分配队列段，消费者持唯一执行权批量取出；同 worker 发送可缩短路径，远程发送减少争用和唤醒次数。热点进程可评估生产者分片后合并。

除队列槽位外，实际消息条数、字节和结构开销也有上限。保留同发送者到同接收者的顺序、完整 Pid 校验和退出线性化；每批限制条数、字节与时间，确保控制信号能及时插入。无锁版本要处理 ABA、段回收和内存序，并与简单队列比较。

### 17. 三级额度的有界预留缓存

**条件实验。** 从租户与 VM 账户预留一段已计费额度，worker 在额度内快速完成本地准入，减少每次分配的全局原子操作。

预留额度时就从上级账户扣除，本地使用仍受微进程上限约束。需要定义闲置额度回收、跨 worker 转移、失败回滚和退出清理。缓存可能造成假性额度不足，慢路径先尝试回收，再按契约报错，不能实际超额。预留阈值会影响准入行为，启用前要更新资源契约。

### 18. 批量唤醒、定时器轮与异步 I/O

**优先实验。** 合并同 worker 的入队通知，使用分层时间轮或其他有界定时结构管理大量 timeout，以共享 I/O reactor 投递完成事件，避免每个微进程一个 OS timer 或线程。

注册、唤醒、取消和关闭按同一套状态协议处理，不能仅因队列非空就省略通知，否则可能丢失唤醒。时间轮的粒度要满足声明的超时精度，不提前触发，并报告迟到和集中触发的成本。批量 I/O 仍逐项执行资源准入和取消。

## 调度与执行上下文

### 19. 亲和调度、批处理与分层窃取

**优先实验。** state 和消息优先留在最近执行的 worker，消息就绪后先在本地调度；跨 worker 分批窃取，减少每次同步的平均成本。热点 actor 的连续执行次数受预算限制。

调度仍要避免其他进程和清理任务饥饿。测试同核、跨核、热点收件人和不均匀负载，重点观察尾延迟和保留的执行栈。平台没有硬亲和能力时使用可移植策略，不承诺核心绑定。

### 20. 带证明的 safepoint 合并

**条件实验。** 为有明确工作量上界的短基本块合并重复检查；长循环保留轮询，动态循环按有界批次检查。结合静态成本预算，减少不必要的原子读取和根维护。

成本预算不能证明墙钟时间上界。优化后检查每条无限执行路径是否都经过 safepoint，重新测量最大检查间隔、取消响应和心跳；不跨无界 native 内建合并检查。时间标志使用正确的原子操作，普通读取和 `volatile` 都不能替代同步。

### 21. 更小的受管切换 ABI

**独立设计。** 评估用专用寄存器保存 context、堆基址和额度，以及切换桩只保存 safepoint 活跃值的方案。这些优化可以减少保存量，但编译器、ABI 与恢复路径必须使用一致的约定。

切换只发生在编译器声明的受管调用边界，不能从任意机器指令直接跳出。Darwin 的 `x18` 等平台保留寄存器不可占用；浮点/SIMD、栈对齐、控制流保护、迁移和调试回溯都要测试。只保存少量寄存器的空切换耗时，不能代表业务切换成本。

### 22. 显式续体与无栈 handler

**独立设计。** 将受管 handler 的暂停点转换为显式状态机，只保存后续仍活跃的值，尝试减少大量被抢占进程保留原生栈的内存成本。

这会改变首版的返回式 handler 模型，也不能直接据此加入 `await`。递归、调用链、异常、精确根、取消和诊断都需要新的表示与 ABI；如果续体需要序列化，还要处理代码版本和 schema。用同一个长 handler 对照原生栈方案，确认收益足以抵消续体分配和分派成本后再决定。

## 平台专用候选

### 23. Apple Silicon 的调度与 AArch64 路径

**条件实验。** 评估 QoS、性能核/能效核下的 worker 数量和窃取阈值，使用合适的 SIMD 或原子指令变体减少编码与跨核同步成本。先做 CPU 特性检测，不把某代芯片特性视为所有 Apple Silicon 的保证。

QoS 和 affinity hint 不是硬绑核接口。测试耗时、热降频、长时吞吐与功耗，空转 polling 只作为可关闭的延迟策略；与 BEAM 比较时，不能靠占满所有核或异常提高优先级取得优势。

### 24. Linux NUMA、核心绑定与 io_uring

**条件实验。** 在适用硬件上评估 NUMA 本地分配、分层窃取、受控绑核，以及 `io_uring` 的批量提交或注册缓冲。`epoll` 保留为默认对照和兼容回退。

根据 cgroup、cpuset 和实际可用资源决定 worker 布局。固定缓冲、队列与每节点缓存全部计费，NUMA 远程引用、取消竞态和退出释放单独测试。这些优化不应阻碍 macOS 的 `kqueue` 实现；NUMA 与 Apple Silicon 的核心分组也需区分。

### 25. 更重的离线编译后端

**独立设计。** 若 Cranelift 生成代码成为已证明的瓶颈，可比较 LLVM 等离线优化后端，在相同受管 IR 上评估更深的向量化、跨过程优化与 profile 引导。先保留 Cranelift 作为构建速度和正确性对照。

新增后端仍要满足 safepoint、精确根、栈限额与代码版本契约，同时评估双平台装载、调试支持和测试成本。只有端到端收益明确时才更换默认后端，不能仅凭局部生成代码判断。

## 实验顺序

| 阶段 | 优先候选 | 需要拿到的证据 |
|---|---|---|
| M0 | 类型与值布局、尾调用、双平台 ABI、基线 profiler | 后端与装载可用，热点可定位，受管检查和根可恢复 |
| M1 | PCB 冷热拆分、小 state 内联、slab、专用消息布局 | 同状态内存斜率、分配次数、通用路径差分与失败守恒 |
| M2 | mailbox 批处理、调度亲和、额度缓存、检查合并 | 同机 BEAM 吞吐/尾延迟、竞争与取消测试、跨核成本 |
| M3 | 压缩引用、冷状态、空页回收、按需增量 GC | 普通 Idle/冬眠内存曲线、压缩与唤醒成本、两平台回收结果 |
| M4 及以后 | profile 特化、只读共享、平台专用路径 | 真实试点收益、长时稳定性、通用回退与诊断完整性 |
| 单独决策 | 移动/分代 GC、stack map、专用 ABI、显式续体、替代后端 | 版本化契约、完整根/所有权证明、维护成本与端到端收益 |

表中安排的是实验顺序，不承诺全部交付。收益不足时保留简单实现；组合优化要先有单项数据、正确性验证和失败回退，才能作为默认方案。

## 不采用的捷径

- 不关闭抢占、栈限额、内存与 mailbox 准入来换吞吐。
- 不用跨微进程可变裸引用实现“零拷贝”，不让 native 库绕过受管边界。
- 不依靠捕获未知 `SIGSEGV` 继续执行，也不把线程池当原生故障隔离。
- 不为所有进程预留大栈、大队列或大页，再只报告逻辑活数据。
- 不将 NaN boxing、指针压缩、AOT、无锁或 SIMD 本身当作已经领先 BEAM 的证据。
- 不关闭 macOS 系统保护、BEAM 正常优化或隐瞒压缩内存与热状态来制造数据。
