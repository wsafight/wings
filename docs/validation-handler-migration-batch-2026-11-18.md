# handler 返回迁移间隔消融（2026-11-18）

## 范围与决定

未采用候选，正式调度仍在 handler 返回后按固定编号迁移。原生栈采样中的通知/锁等待促使本次检查迁移频率：基线 `a3f8dfeaa6182c561dd5152b7bdad43cbcc47cba` 每个 handler 后换 worker；隔离副本的候选每八个 handler 才换 worker，期间每次正常返回后仍释放活栈、重新入队，每轮最多认领一个 handler 并恢复一个时间片。候选给 actor 增加一个计入实际结构大小的 `u8` 计数，其他源码不变；没有去掉 safepoint、取消、计时器或资源检查，没有改当前工作区的实现。

本机 Apple M3 Pro、36 GiB、macOS 26.6.2 AArch64、Rust 1.99.1。冻结两份 release runner、全部源码、候选补丁、编译工具、相同 AOT 产物和驱动，每次运行前后核对 SHA-256。沿原 v6 `hot-queue`：100 actor × 4096 B、90% 发往同一 actor、mailbox 100、pending 256、两个 worker，计划 80000 次/秒，30 秒预热、60 秒采样，原 40 B 事件固定缓冲落盘。CPU 240 秒、墙钟 130 秒、业务阶段 120 秒、文件 10 GiB 和 RSS 安全停止 1 GiB 保持原值。运行期间无本项目并行构建/测试或 profiler。

第一对基线先跑，第二对候选先跑。原计划最多五对，在两对均没有减少采样拒绝且 p999 更差后停止候选；这是筛选失败，不是已完成五对门禁或已证明该策略在所有负载无收益。主机隔离、CPU 硬配额、温度/电源与原生双平台均未验证，没有同轮 BEAM 或完整平台内存采集；辅助 RSS 观察不能当内存门禁，也不能将迟发/拒绝完全归因到 VM。
