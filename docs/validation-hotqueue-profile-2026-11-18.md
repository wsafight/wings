# 2026-11-18 hot-queue 原生采样取证

## 范围和运行条件

本机 Apple M3 Pro、36 GiB、macOS 26.6.2 AArch64，源码为 `b9853b201c06343985a169b0138842277b4e9809`。在具名记录回复及 CLI 输出提交后，用冻结的 release runner、编译工具、AOT 产物和 432 项输入执行原 v6 `hot-queue` 业务：100 actor × 4096 B 状态、mailbox 100、pending 256、90% 请求到同一 actor，Wings 两个 worker。业务、状态与队列限制均未修改。

先执行 10000 次/秒，再执行协议已有的 80000 次/秒；每个速率仅一轮，保留原 30 秒预热、60 秒采样、CPU 240 秒、墙钟 130 秒、业务阶段 120 秒和文件上限 10 GiB。收到 `sampling` 事件后，对该 runner PID 执行 `/usr/bin/sample <pid> 5 1 -file <输出>`，即五秒、每一毫秒请求一个栈样本。进程原始事件仍以原 40 B 格式写文件；独立完整重放核对逐条准入/回复/终态、最终状态、pending 清空和根启动余量，二轮均通过。

这是带 profiler 扰动的路径诊断，未执行五对重复，也未采集同轮 BEAM、整机内存或 CPU 硬配额；主机隔离、热/电源状态未验证。栈样本包含休眠和锁等待，不能解释为线程 CPU 百分比，也不能据此声称最大吞吐、内存门禁或 MVP 已完成。运行期间没有并行启动本项目构建/测试；其他主机活动未隔离。

## 栈采样与下一步

每轮每线程各 4035 个栈样本。10000 次/秒时，两个 worker 在停车分支的样本分别为 3913/3906；80000 次/秒时为 2815/2849。两个速率的 worker 均有大量等待，较低速率不足以给稀少的忙路径排优先级。

80000 次/秒的合并栈顶中，条件变量广播 639 条、信号通知 404 条、mutex wait 719 条、mutex drop 234 条，`State::maintain` 293 条，memmove 395 条。它们是五个线程的墙钟栈样本计数，既不是各类调用次数，也不是互斥的 CPU 用量归因。可优先进一步检查调度器广播、计时通知、状态锁及请求维护与迟发的时序关系；本次没有改调度策略、减少 safepoint、提高预算或恢复已退化回退的通知/空表优化。任何候选仍须独立正确性回归及原同负载配对消融。

## 后续真实对照短测
