# hot-queue、fairness 与候选实验收尾（2026-11-20）

本轮按冻结产物、runner 和负载完成 hot-queue Wings/BEAM 五对、最终 runtime fairness 五对，以及两个相互独立的 Scheduler/结果通知候选 A/B。全部原始 trace、控制输出、失败轮次、逐秒内存和冻结输入保留；没有通过扩大 mailbox/pending/deadline、关闭警告或重跑挑选结果改判。

环境为本机 macOS AArch64、真实 OTP 29，30s 预热/60s 采样、五对交替。没有 OS CPU 硬配额，主机隔离和监测偏差未验收，因此以下是探索性集成基准，不是原生双平台或完整 BEAM/MVP 门禁。

## hot-queue 同业务对照

业务为 100 actor×4096 B、mailbox 100、10000/s、100ms deadline、256 pending、2 worker/2 BEAM scheduler。Wings **5/5 尾候选通过、0 拒绝、0 超时**，BEAM **3/5 通过**，第 2/4 对分别 67/151 次拒绝，全部零超时。

| 指标 | Wings | BEAM |
|---|---|---|
| 端到端 p99 范围 | 36875–50584ns | 5879–14600ns |
| `observed-sent` 服务 p99 范围 | 35916–46167ns | 5333–10041ns |
| 进程树+驱动 RSS 峰值范围 | 46940160–71221248 B | 89980928–111804416 B |
| 物理占用采样峰值范围 | 37061688–38094048 B | 65144392–71337640 B |

Wings 服务 p99 仍明显高于 BEAM，发生器迟发不能解释主要差距。Wings 同轮内存采样较低，但 BEAM 第 1 对平台样本不完整，且口径不含所有主机成本。扫描在基准档出现停止条件，不能据此证明 Wings 最大可持续吞吐更高。完整数据和报告 hash 见[开环服务延迟记录](validation-open-loop-service-latency-2026-11-20.md)。

## 最终 runtime fairness 对照

业务为连续百万次 checked 加法热 actor 和 100 个每 10ms 同刻 burst 心跳 actor，Wings 1 worker、BEAM 1 在线 scheduler。两端各 **5/5 尾候选通过，全部零拒绝、零 pending_full、零超时**。

| 指标 | Wings | BEAM |
|---|---|---|
| 心跳 p99 范围/中位数 | 617500–676042ns / 645333ns | 412672–452833ns / 441469ns |
| 心跳 p999 中位数 | 1550333ns | 2865333ns |
| 热任务完成率范围 | 264.267–272.067/s | 84.967–85.567/s |
| RSS 峰值范围 | 32063488–152813568 B | 131383296–199671808 B |
| 物理占用采样峰值范围 | 22152152–55182368 B | 74974744–92571208 B |

Wings p99 较高、p999 中位数较低，不能只选一个分位宣称整体尾延迟领先。热完成率和每对内存采样呈探索性优势，但不是 CPU 硬配额下的吞吐/完整内存验收。Wings 第 1 对与 BEAM 第 4/5 对存在平台缺样，不补成完整分布。详见[fairness 记录](validation-fairness-measurement-2026-11-20.md)。

## 独立候选结论

| 候选 | 正确性 | 五对主要结果 | 决定 |
|---|---|---|---|
| [ADR-0151](adr/0151-reply-completion-notification-candidate.md) 无等待者结果通知省略 | 修正重复计费后 425 项测试通过 | 服务 p99 中位数候选 80333ns、基线 48667ns；候选 305 次队满、2/5 失败，基线 5/5 通过；内存无稳定改善 | 回退，恢复结果表无条件 finish 通知 |
| [ADR-0152](adr/0152-scheduler-finish-ready-notification-candidate.md) Scheduler finish 新增 ready 才广播 | 425 项测试通过 | 服务 p99 中位数候选 49084ns、基线 80542ns，但基线第 4 对严重退化；候选仅 3/5 通过、741 次队满，RSS 四升一降 | 回退，恢复 Scheduler 无条件 finish 广播 |

ADR-0151 首次部分实验因 `waiters` 重复计费显式作废并保留，正式判断只用修正后的独立目录。ADR-0152 保留基线第 4 对 35615 次队满/490 次超时与候选全部失败，不用中位数掩盖尾候选或内存问题。两个候选的 runner、源码和完整事件均在各自冻结目录，当前 runtime 不含任何候选；恢复后原 424 项 VM 测试与 Clippy 通过。

## 最终判断

- **性能双目标尚未验收通过。** hot-queue 的 Wings 服务 p99 明显较高；fairness 的热完成率优势不能与该负载拼接成统一吞吐结论，也没有最大持续吞吐证明。
- **内存只有同轮探索性优势。** hot-queue 与 fairness 的 Wings RSS/物理占用采样总体较低，但完整整机内存口径、缺样和监测成本仍开放。
- **本轮测量与候选实验已收尾，两个候选均回退。** 当前保留的是 ADR-0150 的离线服务延迟摘要、配对 A/B 驱动和完整证据，不是未经验证的运行时优化。
- CPU 硬配额、主机隔离、饱和吞吐、完整公平性过载分组、完整整机内存和原生 Linux x86-64 对照仍是独立后续门禁；本轮不宣称 BEAM/MVP 达标。
